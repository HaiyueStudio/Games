# 鲸屿制造与马里奥制造 2 的 3D 世界风格功能对照

核对日期：2026 年 10 月 29 日。用途：确定后续需要新增、调整及保留的玩法；本次只整理设计，不改变游戏规则。

后续实现更新：P0 目标 01–03、P1 目标 04–15 与 P2 目标 16–20 已完成，当前行为以 [P0 实现说明](P0_RULES.md)、[P1 实现说明](P1_IMPLEMENTATION.md) 和 [P2 实现说明](P2_IMPLEMENTATION.md) 为准。下表保留核对时的基线；尚未交付的 P3 内容继续按[路线图](SMM2_3D_WORLD_ROADMAP.md)推进。

当前已经具备较完整的平台跳跃、持物、敌人、砖块、机关和编辑器基础。主要缺口集中在 **3D 世界动作与变身、透明管道中的多类对象通行、机关之间的联动，以及冰冻等状态的完整生命周期**。建议先统一这些规则，再扩充敌人与场景零件。

## 参考范围与兼容原则

参考对象是《Super Mario Maker 2》的 **Super Mario 3D World 游戏风格**，包含 2.0.0、3.0.0 增加的零件。这个风格仍在横向二维平面上游玩，适合当前普通 2D 渲染架构。任天堂的[制作说明](https://www.nintendo.com/jp/switch/baaqa/pc/make/index.html)和[追加零件对应风格表](https://www.nintendo.com/jp/switch/baaqa/pc/make/ver.html)用于确认版本与风格；具体交互由各条机制资料补充。

采用以下三类标记：

| 标记 | 含义 | 后续处理 |
| --- | --- | --- |
| 3D 基础 | 制造 2 的 3D 世界风格本身包含的能力 | 优先补齐缺失交互 |
| 保留扩展 | 已按本项目需求实现，但来自其他风格、其他系列或原创设计 | 保留，明确与哪些系统交互 |
| 待标定 | 资料能确认行为，但不能确定准确速度、格数、时长或边缘判定 | 先规定行为，再通过实机逐帧测量定参数 |

既有地图默认保留现有玩法。不能因为参考风格变化就自动移除铁盆、巨型珍珠、旋转踩刺、冰花、流沙、火棍或经典四关。互斥行为需要兼容选项时，再增加明确的关卡规则字段；无需为五种马里奥风格各写一套引擎。

## 冰花与冰球扩展的统一方案

采用 **NSMBU／Deluxe 的冰力玩法**，冻结的基础行为与 Wii 一脉相承。不要混入《银河》中短时冰形态、企鹅装的强化游泳／不打滑，或赛车游戏冰道具。NSMB 系列资料支持冻结普通敌人、挣脱、抱起投掷、冻结飞行怪和水中浮力等差异。[Ice Ball](https://www.mariowiki.com/Ice_Ball#New_Super_Mario_Bros._Wii)、[Ice Mario](https://www.mariowiki.com/Ice_Mario#New_Super_Mario_Bros._Wii)

| 对象／状态 | 当前情况 | 建议统一规则 |
| --- | --- | --- |
| 玩家冰球 | 使用火球弹跳流程，没有反弹次数限制 | 单独的短程冰球；参考 Wii／U 的一次地面反弹后再次落地碎裂。撞墙、命中、出界各只消耗一次；速度、弧线和可同时存在数量另行标定，不沿用火球的全部参数。 |
| 普通地面小怪 | 冻结后一直保留，火球命中才主动解冻 | 冻住后暂停 AI，启动挣脱计时；末段摇晃预警；抱住时暂停计时。解冻恢复原始配置和有效运动状态，不能恢复已经消失的源对象。 |
| 飞行怪 | 立即下落 | 短暂悬空，可作为临时踏脚点；随后坠落。要定义落地碎裂与被搬运的差别，并保留敌人原飞行配置供正常解冻。 |
| 水中怪／落入水中的冰块 | 没有专门浮力 | 向液面浮起并成为实体平台；浸水时采用水中冻结状态，而非继续套地面挣脱倒计时。 |
| 冻结食人花／大型怪 | 大多可冻结、可搬走；解冻管花会脱管 | 建立“小型可搬／管口固定／大型短冻结／完全抗冻”表；管口怪冻结、破冰、解冻与附着信息分开处理。不能对所有种类只检查一个 `frozen` 布尔值。 |
| 冻结炸弹 | 引信暂停已有 | 保留剩余引信，解冻再继续，不重新给满五秒；抱住冻结炸弹时不能同时执行普通红炸弹的投掷或引爆分支。 |
| 投出的冰冻敌人 | 击败敌人、撞墙碎裂、普通砖破坏已有 | 保留；补坐击碎冰、落地重砸、敌人与地形多接触的首次命中处理，掉落物只生成一次。 |
| 火焰敌人 | 冰球消灭跳跃火焰已有 | 保留；补冰球消去敌方火焰／部分火弹的明确类型，避免用任何 `kind: fire` 都可互消。 |
| Boss | 不冻结，但冰球造成伤害 | **按既有需求保留**。这不是 NSMB 冰力通用规则：Wii 中冰球不能伤害或冻结 Boss，U 中部分 Boss 会立即挣脱。自定义 Boss 伤害单独配置，不借“统一冰力”取消已要求的功能。 |
| 冰砖／封冻内容 | 光滑、可融、藏物共享一个类型 | 普通滑冰砖不融化；封冻内容可由火焰解封；冰冻敌人有独立计时。关闭“光滑”仅改变表面摩擦，不应同时改变可融化性。 |

冰球与火球都应经过同一套“弹丸来源、接触目标、有效命中、销毁”流程，但各自使用不同弹道、抗性与状态结果。建议让敌人声明 `freezeResponse`、`canCarryFrozen` 等能力，而不是在多处继续追加种类判断。

## 流沙扩展的统一方案

流沙保留。以 NSMBU 的“影响移动与起跳、可通过连续跳跃挣脱、沉到底部有生命危险”为主要行为参考；3D 世界原作 Conkdor Canyon 也有流沙。不要同时混用《64》的立即吞没深沙或《奥德赛》的动作禁用规则。[Quicksand](https://www.mariowiki.com/Quicksand)

| 项目 | 当前 | 建议 |
| --- | --- | --- |
| 下陷 | 静止 0.25 格／秒，走动 0.125 格／秒 | 保留这组已指定的默认参数；作为沙区的下陷强度，便于后续调关卡。资料未给出这些原版常量，不能标为原作数值。 |
| 深埋跳跃 | 超过 0.5 格后跳高减半 | 保留；验证短按／长按、成长／巨型、普通／旋转跳都按同一高度倍率计算。 |
| 水平移动 | 没有沙内独立水平阻力，仅改变下陷速度 | 补地面／沙内水平阻力和速度上限；区别“走动让下陷减半”与“人物在沙里走得慢”。连续跳应确实逐渐挣脱，不能每次起跳又被表面吸附直接拉回。 |
| 完全埋入 | 玩家死亡，敌人与物品被吞没 | 保留；无敌星和铁盆不能免除窒息；水中呼吸／游泳状态不能误带入流沙。 |
| 敌人与道具 | 共用深度和沉速 | 保留统一基础；测试滚动珍珠、壳、星、POW、箱、雪球、冰冻敌人；浮水物不能因为有浮力就自动浮在沙上。 |
| 沙层内部支撑 | 真正砖块／箱子会托住对象 | 保留；被托住时不能继续累计假的埋入深度并误杀。沙面遮挡与碰撞深度使用同一数据。 |
| 编辑属性 | 连续涂绘，自动连接表面 | 增加可选强度、浅沙／深沙、流动方向；这些是关卡设计扩展，不必作为首轮严格复刻任务。 |

## 雪球与仙人球的补充

雪球本身已经是制造 2 的 3D 世界可用内容，不需要归为“其他系列冰球”。当前推、抱、投、碰敌破碎和触发顶砖均保留。还可补踩停滚动雪球、雪版投球怪／仙人球产生雪球、大雪球只能踢与滚动、雪球命中 Boss 的伤害表。参考机制中雪球撞玩家只推开而不直接扣血，应继续保证不会套铁盆／龟壳的滚动伤害逻辑。[Snowball](https://www.mariowiki.com/Snowball#Super_Mario_Maker_2)

仙人球已有可编辑高度与头／身体击中区别。雪版、带翅膀和冰球抗性尚未覆盖；头部一击消灭、身体一层一击是当前定制规则，保留默认，不用未测量的耐久值替换。[Pokey](https://www.mariowiki.com/Pokey#Super_Mario_Maker_2)

## 交互表与验收场景

每类新增内容至少有以下实际关卡验收：

1. 单体正常行为，以及左右方向、上下接触、最高速度下的连续碰撞。
2. 小型／长高／火／冰／巨型，持物、戴盆和坐盆的组合，不更改已指定碰撞宽高。
3. 砖缝两个实际接触块、墙角、缓坡与陡坡衔接，不能多触发或穿透。
4. 冰冻 → 搬运 → 过门／透明管道 → 轻放／投掷 → 解冻，身份与计时保持一致。
5. 水／岩浆／流沙中的进入、支撑移除、浮沉和死亡，渲染遮挡对应真实碰撞。
6. 玩家离开屏幕、暂停、死亡重试、检查点、编辑器重新试玩，清理临时实体但恢复蓝图。
7. 编辑器复制、移动、撤销、导入导出保存所有配置；旧 version 1 地图继续可用。
8. 2D 世界绘制继续由普通渲染负责，HUD 与编辑属性使用引擎 GUI；素材等比、脚底对齐，动画／弹丸／碎片均有数量和生命周期上限。
