# 谷外之光 · Beyond the Valley

Haiyue 引擎制作的正交投影视觉解谜原型。当前交付包含一关可以完整通关的序章、两个可拖拽机关、可行走的 glTF 旅行者，以及五章剧情手记。第二至第五章是剧情与玩法构想，尚未制作成关卡。

## 启动

在 `Games` 根目录运行：

```powershell
npm run build:target -- game:valley-of-light
node games/valley-of-light/serve.mjs
```

打开 <http://127.0.0.1:4177/>。需使用支持 WebGPU 的浏览器，通过 HTTP 访问，不能直接双击 HTML。端口占用时可在 serve 命令末尾指定其他端口。

游戏已登记到 `games/manifest.json`，大厅使用 `?game=valley-of-light` 进入；正常预览构建会复制 glTF 和游戏资源。

## 操作

| 输入 | 效果 |
| --- | --- |
| 左右拖拽金色圆环或桥面 | 围绕立柱转动金桥，松手吸附到 90° 档位 |
| 沿轨道拖拽青色桥面 | 平移桥梁，松手吸附到半格档位 |
| 点击可达桥面 | 旅行者走向该段道路的中点 |
| 点击光门 /「启程」/ 空格 | 有完整路线时走向出口 |
| Q / E | 金桥向左 / 右转一档 |
| A / D | 青桥向左 / 右移半格 |
| H /「提示」 | 查看解谜提示 |
| J /「旅途手记」 | 查看五章故事；打开时暂停角色行走 |
| Esc | 取消拖拽或关闭手记 |
| R /「重新开始」 | 重置本关 |

鼠标、触摸和笔使用同一套 Pointer Events。拖拽使用 pointer capture；取消触摸、丢失 capture、切换窗口和改变画布尺寸都会回滚未提交的拖拽。角色正在行走，或者站在对应机关上时，不能操纵该机关。

当前安装的 Engine 0.1 GUI 延迟到渲染帧才处理指针事件，可能对已结束的触摸调用捕获 API。`canvasInput.ts` 为本画布的原生捕获方法加活动指针及所有权检查，并在销毁时还原，用于兼容这一版本。它不访问 GUI 私有字段，也不替代 GUI 的输入分发。

解法：金桥转成横向（初始状态按 Q 一次），青桥移到轨道正中（按 D 四次），再点击光门。提示不会代替玩家解谜。

## 正交错觉如何工作

相机固定在 `(1,1,1)` 方向，投影基向量为：

```text
u = (x - z) / √2
v = (2y - x - z) / √6
```

沿 `(d,d,d)` 移动任意距离，屏幕投影都不变。第一处错觉接缝分别位于 `(-0.5,0,0)` 和 `(2.5,3,3)`，第二处位于 `(4.5,3,0)` 和 `(6.5,5,2)`。这两对端点在真实三维空间中分离，却在画面中相遇。

`rules.ts` 只检查相邻道路的预设端口，不把所有画面交叉当成道路。重合阈值使用投影世界单位，不依赖窗口像素大小。角色通过接缝时瞬时切换深度，保持屏幕位置连续；普通路段沿三维路线行走。这是游戏明确允许的视角规则，不是物理碰撞或通用导航系统。

规则与渲染分离，`route()` 生成图上的可达路径；编辑桥梁后立即重新计算连接。引擎 `SingleSlotGameSave` 保存机关档位、角色所在路段、操作次数与通关状态。行走中刷新会回到最近出发的平台，不保存半途悬空位置。

## 角色与 HUD

`assets/traveler.gltf` 是原创的低多边形披风旅行者，戴兜帽、红围巾，提一盏灯；数据使用内嵌 buffer，无外部纹理依赖。

- `Idle`：2.4 秒循环，轻微呼吸和手臂摆动。
- `Walk`：0.8 秒循环，双腿交替迈步，手臂反向摆动和躯干起伏。
- 动画是标准 glTF 节点 TRS 动画，采用关节层级驱动刚性部件；没有蒙皮权重或 IK。
- 用 `createGltfPlugin`、`GltfModelComponent` 和 `applyGltfAnimationClip` 加载、播放和切换动画。
- 重新生成：`node games/valley-of-light/generate-traveler.mjs`。

标题、操作提示、连接状态、操作次数、按钮、剧情手记和通关文案均由 `@haiyue/engine/gui` 绘制。HTML 只提供画布、启动失败提示和隐藏验证结果。中文字符预先加入引擎字体图集。

## 剧情构思

故事取《宽容》序言中“无知山谷与先行者”的主题为出发点，使用原创人物和情节。主角「微」是一名抄碑人；她的勇气来自对地图与现实不一致的追问，而不是天生知道答案。

1. **无知山谷 / 第一道裂隙**：谷里的人只承认祖先走过的路。微发现每年的地图都少一条河，带着灯从被碑石挡住的山口离开。本关以转桥和平移教会玩家第一次质疑“断路”。
2. **无法丈量之城 / 眼睛也会犹疑**：微来到奇异的几何城市，见到同一个位置在不同视角下有不同的连接。后续可加入观察台、可转动相机和多视角机关；她也要承认自己的第一眼并不总是正确。
3. **归来者的审判 / 地图之外的人**：微带新地图回来，被守碑人控告扰乱祖训，关进没有门的塔。归乡关卡重用山谷的建筑，使原本熟悉的安全空间变成牢笼。
4. **没有门的房间 / 让墙成为道路**：她发现铁栏的影子能接上断梯。转水轮、推石台、改变光线，使一个看守亲自走过“不可能”的桥。逃离由理解她的看守协助完成；后续玩法需要把实际道路和影子道路区分清楚。
5. **把山口留给风 / 每个人的远方**：微不摧毁旧地图，也不强迫所有人离开，只留下一张有空白边缘的新图。有人留下，有人开始问河流的名字。结尾让玩家操纵多盏灯一起走向山口，回应从一位旅行者到更多探索者的变化。

宽容的落点是允许提问、允许修正，也允许别人暂时不出发。结局不依靠“另一条不可质疑的新规定”。

## 验证

```powershell
node node_modules/typescript/bin/tsc -p games/valley-of-light/tsconfig.json
node --experimental-strip-types --test games/test/valley-of-light.test.mjs
node games/valley-of-light/verify-browser.mjs --save
node games/valley-of-light/verify-browser.mjs --mobile
```

浏览器验证复用相邻 `Engine` 仓库的 Chrome/WebGPU 测试工具，仅测试脚本依赖它；游戏运行时只使用公开的 Engine/Extensions 导出。验证通过真实 CDP 鼠标或触摸输入操作场景，不通过调试接口直接设置谜题状态。调试接口仅在 `?verify=1` 或 `?verify=save` 时开放，前者禁止存档，后者用于持久化测试。

覆盖：断路阻挡、两种拖拽与吸附、两处错觉连接、Walk/Idle 切换、移动期间机关锁定、完整通关、GUI 手记、重置、取消拖拽、键盘操作，以及存档后刷新恢复。截图和日志输出到被 Git 忽略的 `artifacts/valley-of-light/`。
