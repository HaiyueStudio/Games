# 地图协议 v1 / 精简 v2

根对象：`format: "haiyue-valley-map"`、`version: 1`、`catalogVersion: 1`、`id`、`name`、`objects`、`groups`、`opticalLinks`。标准编号见 `../maps/catalog.json`，完整结构见 `../maps/map.schema.json`，可玩示例见 `../maps/switch-garden.json` 和 `../maps/seaside-garden.json`。

## 坐标与几何

可选根字段 `appearance: {background: "#fae7a0", ambientIntensity: 1.8}` 指定背景与环境光强度。背景必须为六位十六进制颜色；环境强度可省略，范围 0～4，缺省 0.85。完整／精简导出均保留，切换到未配置外观的地图会恢复原默认值。示例 `chapter-two-garden.json` 由地图工坊公开批量 API 生成，见 `../../../tools/valley-editor/API.md`（以 Games 根目录定位工具文档）。

- Y 向上，单位为格。`position` 是路径中心线的局部原点在所属父节点坐标系中的位置（未分组时为世界坐标）；`rotation: [x,y,z]` 使用度，作用顺序为 Z → X → Y，与矩阵 `Ry × Rx × Rz` 对应。
- 一格普通路径默认 `length = width = thickness = 1`，是完整立方体；顶面 Y=0，底面 Y=-1。普通方块和机关平台的六个面各有独立的边中点及面中心通路，三棱柱同样支持其五个面；同一物体的不同面不直接相连，需要曲线路径改变朝向；经过三角面时直接连接入口和出口，不强制绕行重心，因此拼合为完整直路的两个半块保持投影直行；主动选择三角面作为终点时仍停在面中心。当前没有自由地面导航或物理碰撞。
- 楼梯从左端 Y=0 开始，到右端 Y=`rise` 结束，包含真实台阶高差。
- 5 号三棱柱是完整方块沿竖直对角面 `x/length = z/width` 切成的半块，`prismHalf: "a"` 占 `x/length ≤ z/width`，`"b"` 占另一半。两者都是直角三角形顶面、竖直侧面的三棱柱，体积各为原方块的一半。其定位锚点仍是未旋转方块的顶面中心；旋转轴心是所在方块的几何中心，即相对 `position` 的 `[0,-thickness/2,0]`，A/B 半块共用这一轴心，不使用三棱柱自身的重心。旋转不改变所在方块中心；角色停靠点位于当前行走面的中心，三角面使用重心。
- 扭转路径沿 X，截面绕自身中心从 0 连续扭到 `twist` 度，中轴始终为 `[x,-thickness/2,0]`，不随扭转侧移。行走面为 `[x,(cos(a)-1)*thickness/2,sin(a)*thickness/2]`，法线为 `[0,cos(a),sin(a)]`；例如单位厚度转 90°，末端为 `[length/2,-0.5,0.5]`，可以连接同轴方块的 Z+ 侧面。圆弧位于 XZ 平面，中心线为 `[radius*sin(a),0,radius*(1-cos(a))]`，`a` 从 `-arc/2` 到 `arc/2`。圆弧长度由半径和角度决定，不使用 `length`。
- 圆弧另有可选的 `arcTwist`（-360～360 度，缺省 0），从起点到终点逐渐翻转截面，可以衔接侧面；旧地图缺省时仍为平面圆弧。
- 曲线路径至少采样 32 段，扭转路径按角度自适应增加采样（单段翻面 ≤7.5°），并插入每格停靠点；渲染及行走共用样本。`twist` 支持 ±36000°，保留完整圈数；圆弧 `arcTwist` 仍为 ±360°。角色的脚位于实际外表面的中心线上，并随扭转后的曲面法线改变朝向。渲染挤出中轴与脚下轨迹分开定义，避免厚度绕顶面旋转导致斜移。

默认构件的 X/Z 位置是整格中心，Y 是行走面参考高度。复制偏移整格，拖动按锚点的绝对位置吸附；多选拖动保持彼此偏移，Y 不变。「对齐网格」可将所选物体的 X/Y/Z 吸附到当前网格，支持撤销。导入保留旧地图的精确坐标，组轴心可以合法地处于半格。

## 分体方块

编辑器中选择未旋转的 1×1×1 普通方块，点击「拆为 A / B 三棱柱」。A 保留原 ID、位置和所属组；B 获得独立 ID，初始不分组，并沿默认等轴视线偏移 `[d,d,d]`。例如 A 位于 `[0,0,0]`、B 位于 `[3,3,3]`：它们实际不相接，但在默认等轴正交投影中仍组成一格完整方块。

两个半块都可以继续单独移动、旋转、归入不同物体组。导出保存两个独立的 5 号实例及其 `prismHalf` 和变换，对角切面会按实际变换自动识别，也保留 `aEnd:4 / bEnd:4` 显式连接。A/B 是局部几何定义，旋转后的两个 A 也可以构成互补接缝。它们不是完整立方体的重叠，也不是体积完整的楔形。切面投影及半块朝向不匹配时，角色不能穿越；只让切面中点重合不足以连接。

`split-cube.json` 是可通关的分体方块示例，用于验证这类不可能几何的基本拼接。旧 JSON 的显式长宽厚会保留；缺省 `prismHalf` 按 A 半块读取，不会自动缩放用户已经制作的地图。

## 配色与手轮

每个实例的可选 `colors` 包含五个 `#RRGGBB` 字段：`surface`（路径主体）、`hub`（中空轮毂）、`spokes`（方杆和转轴）、`tips`（四个末端方块）、`base`（墙面轴座）。旧 JSON 缺省时补入默认配色，导出总是保存完整配色。1～12 号中除 3 号旋转机关外只使用 `surface`；13～16 号按下表使用部位配色；17 号用 `surface` 表示梯框、`hub` 表示横档。

3 号手轮由八边形轴座、方转轴、中空多边形轮毂及四根方杆组成，未旋转时转轴方向与局部 `motion.axis` 一致：X/Z 安装在侧面，Y 安装在顶部。实例 `rotation` 会绕路径块的几何中心旋转整个平台、轴座和手轮，块中心保持在 `position + [0,-thickness/2,0]`；局部转轴随实例朝向及所属组一起变化。转轴穿过手轮路径块的几何中心（单位块在顶面锚点下方半格），所控制的道路/物体组绕这个中心旋转；不使用目标组的 `pivot`。手轮装饰伸出格子边界，但不会改变路径顶面中心锚点或通行端口。

试玩时必须按住轮毂或轮臂，以手轮投影到屏幕的中心为圆心绕动。角度取连续指针极角差，跨越 ±180° 不跳变，可正反向连续旋转任意圈数，角度持续累计，松手再按住仍从已有角度继续；径向拖动不转动；松手按 `step` 吸附。鼠标和单指触摸共用同一交互，取消手势恢复拖动前角度。

## 物体组与机关

组是可为空、可嵌套的父节点：`id`、`name`、`pivot` 保持原字段，新增可选 `parentId`（默认 null）、`position`（默认 `[0,0,0]`）、`rotation`（默认 `[0,0,0]`）和 `scale`（默认 `[1,1,1]`，每轴 0.01～100）。物体通过 `groupId`、子组通过 `parentId` 指向父节点。ID 在物体与组之间也必须唯一；拒绝不存在的父节点、父子循环和机关循环依赖。

节点内先执行开关绕 `pivot` 的旋转和相对位移，再执行父节点的缩放、Z→X→Y 旋转及位置平移，递归继承祖先变换。运行时手轮的旋转中心仍来自其路径块，驱动目标组及其全部后代。旧组缺少新增字段时为恒等变换，旧地图不改变位置。

编辑器编组、拖换父节点及剪切粘贴保留世界几何。可选 `basis` 为 16 项列优先可逆仿射矩阵，包裹节点自身的变换，用于精确保留非均匀缩放后的旋转或剪切；通常只有重新归组时需要，消费端需保留并应用，不能只提取位置。可选 `order` 保存同级节点显示顺序，不影响渲染与寻路。渲染、射线拾取、通路端口和法线使用同一套层级变换（法线使用逆转置）。

复制父节点会递归重建子节点 ID，重映射内部 `targetGroup`、开关动作、立柱依附及错觉接缝；对复制范围之外仍存在的机关引用保留。删除父节点会删除整个子树并清除外部失效引用。

3/4 号物体的 `motion`：3 号的 `axis` 指定机关自身的局部 X/Y/Z 转轴，实际驱动方向随机关朝向和所属组变换；4 号的 `axis` 指定世界 X/Y/Z 平移轴；`min/max` 仅限制 4 号平移机关相对初始状态的行程，3 号手轮始终连续旋转（旧 JSON 中的这两个字段保留但不作为旋转限位）；`step` 为松手吸附间隔；`targetGroup: null` 只驱动自身，填写组 ID 则驱动整个组。旋转值单位为度，平移值单位为格。角色行走、开关动画播放、关卡结束，或者角色位于被驱动对象/组上时禁止拖动。3 号手轮的 disabled 显示状态自动跟随这一判定：不可转动时四根轮臂和端头在 0.36 秒内收进轮毂，恢复可转动时展开；中途改变状态会从当前伸展量反向过渡，保留旋转角度与受控道路姿态。禁用轮毂不响应旋转或行走指令，拾取范围随当前伸展量变化。停止试玩恢复完整轮形用于编辑；这是运行时显示状态，不写入地图 JSON。

8 号物体的 `trigger.actions` 示例：

```json
{
  "mode": "once",
  "actions": [{
    "groupId": "bridge",
    "translation": [0, 0, -3],
    "rotation": [0, 90, 0],
    "duration": 1.5,
    "easing": "smooth"
  }]
}
```

角色到达按钮中心才触发。`once` 每次试玩只触发一次；`toggle` 离开后重新踩入，在目标姿态和初始姿态之间切换。目标位移/旋转始终相对地图初始状态，不累加；每个开关最多 20 个动作，同一组不能重复。动作同时开始，可分别设置时长；`smooth` 使用平滑起止，`linear` 为匀速。如果组上有角色，角色随该组一起移动。新开关开始时暂停原有行走路线，动画结束后重新选择道路，避免沿旧路径走进空中。

多个开关可控制同一组，后触发者从当前姿态动画到自己的目标。拖拽控制同组时，其参数作为开关姿态上的额外位移/旋转。

## 海面与立柱

11 号是不可行走的海面，`length/width` 控制范围，`colors.surface` 控制颜色。`water` 包含 `amplitude`（0～0.4 格，默认 0.08）、`speed`（0～3，默认 0.65）、`wavelength`（1～20 格，默认 4）；编辑、试玩及独立游戏中均持续轻微起伏。可选 `facetSize`（0.2～4，缺省 0.8）控制三角切面尺寸，`contrast`（0～1，缺省 0.7）控制明暗对比，`lightColor/darkColor` 为亮暗面的 `#RRGGBB` 配色，缺省时根据主色自动生成。旧地图不要求新增字段；v1/v2 均保存自定义设置。

海面使用确定性的不规则三角网格，各三角面拥有独立法线与恒定配色，共用一张小型调色板纹理和一个 Mesh。GPU 形变保持共边位置一致，并同步更新切面法线；每片海面最多 4608 个三角形。JSON 只保存范围、样式及波浪参数，不存顶点数组。

12 号是不可行走的纤细立柱，`rise` 为高度（0.1～20），`width` 为柱径，`colors.surface` 为颜色。可作为独立装饰，或用 `attachment: {pathId, corner}` 逐根依附于 1 号普通路径或 9 号出生平台。角编号 0/1/2/3 分别为 X−Z−、X+Z−、X+Z+、X−Z+；每条路径的每个角最多一根。编辑器新放置的立柱在局部 X/Z 方向各向路径中心内缩 0.1 格，作为显式 `position` 偏移写入地图；尺寸不足 0.2 格时内缩到中心，不越过中心。导入旧地图不额外改变位置。附着立柱的 `position/rotation` 为相对角点的局部偏移/旋转，`groupId` 必须为 null，变换自动跟随路径及其物体组。复制路径同时复制其立柱，删除路径同时删除其立柱；将路径拆成三棱柱时，原立柱保留在世界位置并解除依附。这些操作均支持撤销。

旧地图缺少 `water` 或 `attachment` 时分别采用默认参数和 null。`seaside-garden.json` 展示四角立柱及转动手轮 90° 后落成道路的桥。

## 梯子路径

17 号为可上下通行的梯子，`position` 为梯脚的墙面中心，局部 Y 为爬升方向，Z+ 为墙外。`width` 为梯宽（默认 0.65），`rise` 为爬升高度（0.1～20，默认 2），`steps` 为横档间隔数（默认 8）；实际横档数为 `steps+1`。`colors.surface/hub` 分别控制梯框和横档。几何按这两个材质合并，横档数量不增加 Mesh 数。

起点端口 0 为 `[0,0,0.5]`，终点端口 1 为 `[0,rise,0]`，两端法线均为 Y+，分别连接上下道路的顶面边缘。攀爬段在墙外 Z=0.24，前后短段负责走近与离开梯子。编辑器贴墙时沿外法线保留 0.02 格间距，避免墙面闪烁，仍在自动连接容差内。整体方向跟随实例及父节点变换。

角色在垂直段播放 glTF 的 `Climb`，始终面朝局部 Z−，下梯反向播放，速度为平路的一半；停在横档时暂停动作，重新选择路线可以无跳变掉头，上下平台恢复 Walk/Idle。`ladder-garden.json` 是可通关的两层庭院示例。

## 错觉连接

`opticalLinks: [{a:"road-a",aEnd:1,b:"road-b",bEnd:0}]` 明确声明可发生视觉连接的端口：普通方块的 `0/1/2/3` 分别为局部 `X−/X+/Z−/Z+`；楼梯、圆弧、扭转道路和梯子只使用 `0` 起点和 `1` 终点；半块 A 有 `0/3/4`，半块 B 有 `1/2/4`，其中 `4` 是对角切面。扩展面端口使用 `10 × 面编号 + 边编号`：面编号 1 为底面，2/3 为 X−/X+，4/5 为 Z−/Z+，6 为三棱柱斜切面；底面边 0～4 对应原顶面规则，竖直面边 0/1 为轮廓两端的竖边，2/3 为顶部/底部横边。原 0～4 编号保持兼容，导入会检查端口是否属于该构件。

世界距离小于 0.065 格且法线同向的端口自动相连；显式错觉接缝还要求屏幕投影距离小于 0.055 格。默认等轴投影为 `u=(x-z)/√2`、`v=(2y-x-z)/√6`；视角旋转时使用引擎相机的实际右/上向量重新投影。三棱柱切面的完整投影重合且两半占据相反投影区域时，切面边界自动形成接缝，包括正好接在该边界上的普通道路。跨缝两侧必须有同向的可行走面；普通画面重叠不自动成为路口。

跨越错觉接缝时改变角色三维深度而保持屏幕位置连续。每次选择道路都从当前姿态重建连通图；行走中再次点击时，从当前所在线段的两个端点分别规划，选取剩余行程较短的一侧，因此可立即掉头且不会跳回上个节点或斜穿拐角。切换目标时保留脚的位置与法线；连续点击仍使用当前线段两端，曲面与错觉接缝规则不变。不可达目标保留原路线；机关动画期间暂停选择新路线。编辑器与地图游戏均提供旋转视角和复位等轴视角；自由旋转的临时相机状态不写入地图 JSON；指定的阶段镜头写在 `stages` 中。为避免跨缝过程中改变投影，角色行走或机关动画期间暂停视角旋转与复位。

## 校验与加载

最多 500 个对象、100 个组、1000 条错觉接缝。拒绝未知版本/编号、重复 ID、悬空组与端点引用、非有限数值及越界参数；ID 为 1～64 位字母、数字、下划线或连字符，并保留 `__proto__`、`constructor`、`prototype`。导入失败保留现有地图。Schema 校验结构，跨对象引用及 ID 唯一性由共享 `parseMap` 校验。

试玩要求恰好一个出生平台、至少一个出口，并且所有开关有有效的非空目标组。运行时可通过 GUI「载入地图」选择本地 JSON，或在游戏页面追加 `?map=./maps/switch-garden.json` 从同源 URL 加载。URL 模式也会进行相同校验。


## 精简导出 v2 与静态渲染

默认「精简导出」生成 `version: 2`、`catalogVersion: 1` 的 JSON。对象至少包含 `id` 和数字 `type`，其余字段仅保存与 `createObject(type,id)` 的目录默认值不同的部分；配色、机关、水面和触发器字段也按子字段省略默认值。空 `groups`、`opticalLinks` 可省略。保留 ID、顺序、名称、全部非默认参数、层级、精确坐标和引用，不对浮点数取整。目录默认值属于版本约定，变更默认含义时须升级目录版本，不能改变旧精简地图的解释。

```json
{"format":"haiyue-valley-map","version":2,"catalogVersion":1,"id":"tiny","name":"小径","objects":[{"id":"road-1","type":1,"position":[2,0,0]},{"id":"road-2","type":1,"position":[3,0,0]}],"render":{"version":1,"batches":[[0,1]]}}
```

`render.batches` 保存同表面材质的静态物体在 `objects` 中的零起点索引。静态候选为 1/2/5/6/7/12 号；任意祖先组受手轮、平移机关或开关动作控制时，整个子树均排除，附着立柱继承宿主路径的动态状态。海面、机关、按钮、出生与出口装饰独立渲染。导入校验静态计划与当前构件一致，拒绝过期或篡改的计划；手工修改精简数据后可移除 `render` 重新分析。完整 v1 地图加载时也会自动分析。`parseMap` 将两种格式恢复成相同的完整 v1 内存结构，并为 v2 添加已验证的 `renderPlan` 加载提示；重新编辑/完整序列化时删除该提示。精简 Schema 为 `../maps/compact-map.schema.json`，引用相邻完整 Schema 的共享字段约束。

编辑器试玩和独立游戏将候选几何变换到世界坐标，在专用 Worker 中按表面颜色、剔除方式和正面方向合并。真实空间中，轴对齐方块的完整贴合面被消除；同法线、同材质的矩形外表面继续合并。保留六向外表面、颜色边界、凹角和孔洞。非轴对齐构件、三棱柱、曲面和柱子保留原三角形，仅合批；不近似简化曲面，不把投影重合当成实体接触。大于一个子网格的剔除状态不同（如三棱柱双面端盖）时会分批，以保持原画面。

合并只替换渲染 Mesh，原对象 ID、几何拾取代理、行走拓扑及错觉深度修正仍存在。编辑状态保留独立网格供选择高亮和修改。进入试玩后异步编译，成功时替换；失败保留原渲染，调试快照暴露错误。切换地图、停止试玩或销毁视图会终止旧 Worker，避免迟到结果修改当前地图。姿态未变化的帧复用变换结果；海面和角色动画继续正常更新。导出文件存参数和合并计划，加载时再生成顶点数据，避免将大数组写回 JSON。


## 出生与出口记号

在已有实体道路上添加可选 `marker: {kind: "spawn" | "exit", face: number}`，不改变其 `type`、几何或材质。`face` 为局部面编号：0 顶面、1 底面、2 X−、3 X+、4 Z−、5 Z+，三棱柱另有 6 斜切面；必须是该构件实际存在的面。地图试玩要求恰好一个出生记号和至少一个出口记号。角色在出生记号所在面的中心出现，并仅在到达出口所标记面的中心时通关，走到同一方块其他面不会通关。

9 / 10 号旧平台读取为面 0 的出生 / 出口记号，保留原变换、颜色和 ID；编辑器新建记号直接写在普通路径的 `marker` 属性上，修改或移除旧平台记号时其类型转为 1。旧出口自带的门不再显示，门由独立的 18 / 19 号装饰物负责。

记号跟随路径层级变换，不参与导航拓扑的生成。合并静态道路时仅合并路体，记号保持独立显示。v1/v2 均保存可选记号，缺省时普通路径没有记号。`gate-garden.json` 展示 720° 扭转、两个普通路径上的记号及独立的拱门/方门。

## 传送门与流动水体

新增固定编号：20 传送门、21 水流、22 瀑布。18 / 19 仍为纯装饰门。

20 号使用 `portal: {pathId: string | null, face: number, targetId: string | null, shape: "arch" | "square"}`。`pathId` 是可标记路径，`face` 为已有面编号；每个面只允许一扇门。`targetId` 指向另一扇 20 号门，连接是单向的，双向配对写入两个引用。门的目的地与关卡通关出口分离。缺省是未绑定、未连接的拱门；允许保存未完成地图，试玩时要求所有门已绑定，并且至少有有效出站或入站连接。

已绑定门以宿主面中心为原点、面法线为局部 Y；`position` 必须为 `[0,0,0]`、`groupId` 为 `null`，不能有 `basis`，层级显示在宿主下面。局部旋转用于门的朝向。门的路径节点来自宿主面的中心；门体不增加道路。寻路添加显式单向传送边，角色在 0.4 秒收缩后更换位置和表面法线，再用 0.4 秒出现；不存在穿过空中直线的移动。落地不自动触发返回传送。转场期间的新点击在到达后处理，落地仍会触发对应出口记号或踩踏开关。

21 的 `length/width` 表示水道长度与宽度，沿局部 X 正方向流动。22 的 `length/rise` 表示水幕宽度与向下落差，原点为顶部中心，底部在局部 `y = -rise`。两者使用 `colors.surface/hub/base` 表示水色／流纹泡沫／暗面；使用 `water.speed/amplitude/facetSize` 控制速度／起伏／切面，流动水体实际起伏限制到 0.04 格。速度 0 停止动画。21 / 22 不生成端口，不参与静态道路合并。

精简 v2 的 `portal` 子字段也省略默认值，加载时恢复目录默认值并校验跨物体引用。示例为 `portal-garden.json`。

## 事件规则与初始状态（v1 / v2 可选扩展）

物体可带 `state: {enabled?: boolean, visible?: boolean, walkable?: boolean}`，三项默认均为 `true`。`enabled` 控制机关、开关、传送门和出口记号是否工作，不等同于路径关闭；`visible` 为 false 时不渲染、不参与通行；`walkable` 仅控制路径通行。附着门和柱子继承宿主的隐藏状态。

根字段 `logic` 包含 `variables` 与 `rules`。变量为 `{id, name, initial}`，初值类型为布尔或数字，运行中不得改变类型。变量、规则、物体和组的 ID 不得冲突。规则为：

```json
{
  "id": "open-bridge", "name": "两灯开路", "enabled": true, "once": true,
  "event": {"type": "switch", "source": null},
  "condition": {"kind": "all", "conditions": [
    {"kind": "switch", "objectId": "plate-a", "value": true},
    {"kind": "switch", "objectId": "plate-b", "value": true}
  ]},
  "actions": [
    {"kind": "wait", "duration": 0.4},
    {"kind": "move", "groupId": "bridge", "translation": [0, 1, 0], "rotation": [0, 90, 0], "duration": 1.2, "easing": "smooth"},
    {"kind": "state", "targetId": "gate", "property": "enabled", "value": true},
    {"kind": "message", "text": "新的道路已经开启。"}
  ]
}
```

`event.type`：`start`、`enter`、`leave`、`switch`、`portal`、`mechanism`、`group`、`variable`、`signal`。`source: null` 表示任意匹配来源；start 必须为 null，signal 必须为信号名称。enter / leave 可带 `face`（0～6），按路径和表面切换触发，不按每个内部采样点触发。开始时先发送 start，再发送出生表面的 enter。switch 在开关状态改变后发送；portal 在 0.8 秒转场结束后发送，source 是进入的门；mechanism 在拖拽松手吸附后发送；group 在对应组动画完成后发送；variable 仅在值真正变化时发送。

条件的 `kind`：all / any 使用 `conditions` 数组，not 使用 `condition`；空 all 为真、空 any 为假。variable 使用 `id / op / value`；switch 使用 `objectId / value`；state 使用 `objectId / property / value`；mechanism 使用 `objectId / op / value`。`op` 为 eq / ne / gt / gte / lt / lte；布尔值只支持 eq / ne，数字比较不做隐式类型转换。

动作的 `kind`：variable 使用 `id / operation / value`，operation 为 set / add / toggle；state 使用 `targetId / property / value`，targetId 可指物体或父节点；move 复用旧动画参数；wait 使用 duration 秒数；sequence / parallel 使用 actions；signal 使用 name；message 使用 text；rule 使用 ruleId / enabled。根 actions 为顺序执行，parallel 等待所有子项。相同组的动画排队，在真正开始时采集起始姿态。旧 trigger.actions 保持一次／切换行为，并接入同一动画队列。

每条规则同一时刻最多运行一次。once 在条件满足、开始执行时消耗；停用规则不取消已经运行的动作，也不恢复 once 次数。信号与变量变化进入队列，避免递归调用。运行时实例持有变量、状态覆盖、执行次数、事件日志与等待任务，不修改地图数据；重启丢弃整个实例。变量最多 64 个、规则最多 100 条，树深度最多 6，树节点总计最多 2048；每个动作列表最多 64 项，每组条件最多 32 项。每次调度最多 2048 次事件／动作启动；循环超限后停止调度并报告错误，行走仍可继续。

visible / walkable 关闭若涉及角色当前路径或占用线段，则延后到离开后执行；再次设为 true 可撤销待应用的关闭。关闭尚未进入的路径会阻断已规划路线。正在传送时保护出入口的承载道路，转场结束后再应用关闭。物体组移动开始前等待角色抵达当前行走段端点，移动时角色跟随脚下物体。

完整与精简格式均保存 logic 和 state，不保存运行结果。精简静态分析递归扫描动作树，排除所有可能被移动或隐藏的物体和附着立柱；旧地图无 logic 时保持原有协议和行为。协议示例：`../maps/logic-garden.json`。


## 检查点与局部重置（v1 / v2 可选扩展）

可行走实体表面可设置 `checkpoint: {name: "归途灯塔", face: 0}`，适用范围与出生／出口记号一致。角色经过该表面的中心时保存最近检查点；出生点本身带检查点也会保存。它是独立记号，不新增路块，不修改路径连接或碰撞；蓝色六边形与静态路面批次分开渲染。支持完整／精简导出、复制和立方体拆分（检查点仅归属其中一个半块）。

新动作：

| 动作 | 参数 | 行为 |
| --- | --- | --- |
| `checkpoint` | `name` | 请求保存检查点；当前线段或传送完成后，在安全的路径采样点保存 |
| `restore` | 无 | 整体恢复最近检查点；尚无检查点时恢复关卡初始化后的起点状态 |
| `reset` | `groupId`, `returnPlayer` | 指定父节点及后代恢复地图初始状态；可选择让角色返回最近检查点的落点 |

`restore` / `reset` 是执行边界，触发它们的当前规则不再执行后续动作。整体恢复后继续检查点中保存的其他任务。角色恢复会取消旧路线、传送和点击反馈；不会重放开始、踩踏或进入表面事件。局部重置会先等当前行走段／传送结束再应用。`returnPlayer` 只使用检查点的路径与表面索引，在当前场景姿态下计算位置，不回滚其他区域；检查点不可用时尝试起点，仍无可行走落点则不应用本次重置。

变量与规则可带 `resetGroup: "west"`，指定局部重置归属。该父节点或其祖先重置时，变量回到 initial，规则恢复初始 enabled、清除执行次数和正在运行的动作。未指定归属的全局进度保持不变。物体组位移／旋转、后代物体状态、附着装饰物、开关触发次数与值一并恢复；组外直接驱动该区域的手轮／平移机关和旧式踩踏动画开关也会复位。与区域相关的动作任务和动画被取消，包括尚在等待、但后续会直接修改该区域的任务；其他区域任务继续。取消一个跨区域并行任务会取消它尚未完成的所有分支，应把需要独立重试的任务分为不同规则。

新增事件 `checkpoint` / `restore` 的 source 是保存／恢复落点的路径 ID；`reset` 的 source 是重置请求的父节点 ID。三者允许 source 为 null 匹配任意来源。检查点事件动作完成当前调度后才抓取快照，因此该事件里的变量修改也会保存。重置恢复变量本身不逐项触发 variable 事件，可用 reset 事件重新计算跨区域条件（示例中的出口）。连续自动恢复超过 8 次会停止逻辑并报告循环，避免恢复事件反复重置。

检查点包含角色路径采样点与朝向、组／机关姿态、物体状态、开关、延后关闭的道路、变量、规则启用与次数、等待剩余时间、顺序／并行任务游标，以及活动／排队组动画进度。快照不保存旧行走路线和自由旋转的临时摄像机姿态，也不会写回地图；配置阶段镜头时按恢复后的阶段镜头定位。运行时以脚下路径重算位置与朝向，因此也支持侧面、梯子和移动平台上的安全采样点。

独立地图游戏保存最近检查点到浏览器本地存储，刷新或再次载入同一地图时恢复；「重新开始」清除该存档。存档使用 `haiyue-valley-checkpoint` v1 格式和基于完整地图内容的双哈希标识。地图配置改变、损坏存档或未知任务结构不会应用；任务执行内容始终取自当前已校验地图。编辑器试玩仅在当前试玩会话保留检查点，停止试玩后丢弃。示例：`../maps/checkpoint-garden.json`。


## 移动平台与场景阶段（v1 / v2 可选扩展）

平台使用已有父节点及其全部后代，新增 `groups[].platform`，不新增物体编号：

```json
{
  "initialStation": "lower", "mode": "manual", "autoStart": false,
  "stations": [
    {"id": "lower", "name": "下层", "translation": [0,0,0], "rotation": [0,0,0], "duration": 2, "wait": 1},
    {"id": "upper", "name": "上层", "translation": [0,2,0], "rotation": [0,0,0], "duration": 2, "wait": 1}
  ]
}
```

站点 ID 在平台内部唯一。位移／旋转使用原有 GroupPose 语义，相对父节点初始姿态，并受父级变换影响。`duration` 是从上一姿态到达此站的秒数（0.1～60）；`wait` 为抵达后的最短停站时间（0.1～300），初始站点同样等待。采用平滑插值；旋转按给出的角度插值，允许超过整周。每个平台 2～16 站，不允许平台层级嵌套。

`mode` 为 `manual`（仅呼叫）、`pingpong`（沿站点顺序往返）、`loop`（末站回首站）；`autoStart` 使后两者进入关卡即自动运行。手动呼叫按先后顺序排队，最多 64 个，优先于自动下一站；暂停保持行程、队列和当前位置，继续后接着执行。去当前站的呼叫直接完成，不发出到站事件。平台及其祖先／后代不得同时被拖拽机关、旧触发动画或 `move` 动作驱动，导入会拒绝这些冲突。

导航在平台停靠时按物理接缝和错觉接缝规则连接；行程中（包括暂停在半空）禁用外部连接及附着传送门。角色正在跨越平台边缘时延后出发；已计划但尚未进入的路线在安全端点取消。乘客站在原表面采样点，位置、法线及朝向跟随平台变换，途中不接受行走指令；无乘客的平台不阻塞其他区域的行走。

根字段 `stages`：

```json
{
  "initial": "ascent",
  "items": [
    {"id":"ascent","name":"乘云而上","groups":[],"entry":null,"camera":null},
    {"id":"garden","name":"打开庭院","groups":["courtyard"],"entry":null,
     "camera":{"target":[2,1.7,0],"yaw":65,"pitch":54.73561,"span":10,"duration":1.2,"lock":true}}
  ]
}
```

最多 32 阶段，ID 与组、物体、变量、规则全局不重名。所有 `groups` 的并集为阶段控制区，当前阶段列出的区才可见、可通行；从未列出的区和未编组物体为公共场景。区域根不能互相嵌套，附着门与立柱继承宿主阶段。`state.visible=true` 不绕过阶段隐藏；离开某阶段不重置状态，隐藏的平台暂停计时，重新显示时继续。编辑状态显示全部对象。

`entry` 为 `null`（保持脚下位置）或 `{objectId,face}`（可标记道路的有效表面中心）。切换等待当前行走段／传送／组动画以及角色乘坐的平台结束；若候选落点隐藏、不可行走或平台未停靠，切换不生效并终止请求它的后续动作。初始化使用出生记号，初始阶段必须显示该路径。阶段入口不补发路径进入、开关和检查点事件，使用 `stage` 事件编排抵达逻辑。

`camera` 为 `null`（保持镜头）或指定镜头：target 世界坐标，yaw 水平角（±36000°）、pitch 俯视角（10～80°）、span 正交可见高度（3～150 格）、duration 秒（0～10）、lock 是否锁定。镜头按最短水平转角平滑插值，过渡时阻止角色操作，锁定后禁用旋转、平移、缩放与复位。相机使用公共引擎 API，编辑器和游戏共用同一实现。

| 扩展 | 格式与行为 |
| --- | --- |
| 出发／到站事件 | `event:{type:"departure"或"arrival",source:平台组ID或null,stationId?:站点ID}`；出发事件的站点指目的站；限定站点时必须指定平台 |
| 阶段事件 | `event:{type:"stage",source:阶段ID或null}`；首次初始化及成功切换时发送，恢复检查点不重放 |
| 平台条件 | `{kind:"platform",groupId,stationId}`；站点 ID 表示已停靠，null 表示行程中（含半空暂停） |
| 阶段条件 | `{kind:"stage",stageId,status:"active"或"visited"}` |
| 平台动作 | `{kind:"platform",groupId,command:"go"或"pause"或"resume",stationId}`；go 指定目的站并等待到站，其他命令 stationId 为 null 并立即完成 |
| 阶段动作 | `{kind:"stage",stageId}`；等待安全切换和镜头完成后执行后续动作；同一阶段不重复触发 |

检查点增加平台姿态、站点、活动行程、暂停标记、剩余停站时间、队列，以及当前／已到达阶段。可在平台半途保存并恢复继续运行；阶段切换和镜头尚未结束时延后保存。检查点事件自身触发的阶段切换也先完成再保存，不重复发送保存事件。恢复按对应阶段的配置镜头定位。局部重置恢复范围内平台的初始站姿态、自动运行设置和停站时间，取消有关呼叫，保留全局阶段与其他区域行程。

精简格式保留可选 platform / stages；旧地图没有这些字段时保持原行为。静态分析排除平台与全部阶段控制区及附着构件，其他公共路径仍可合并。示例：`../maps/journey-garden.json`。

## 剧情、选项与旅途目标（v1 / v2 可选扩展）

根字段 `story` 保存对话与目标配置，不包含运行结果：

```json
{
  "dialogues": [{
    "id": "invitation", "name": "未画完的地图", "speaker": "微",
    "lines": ["地图上没有的路，也可以亲自去看看。"],
    "choices": [{"id":"together","text":"邀请守碑人同行。","signal":"invite-keeper",
      "condition":{"kind":"objective","objectiveId":"light","status":"done"}}]
  }],
  "objectives": [{"id":"light","name":"点亮石灯","description":"让守碑人亲眼看见。","initial":"active"}]
}
```

对话和目标 ID 与物体、父节点、变量、规则及阶段全局唯一。选项 ID 只要求在所属对话内唯一，`signal` 为合法信号名或 null；`condition` 必填，编辑器新选项使用恒真的空 all 条件。目标状态为 `hidden` / `active` / `done`。两类配置均可指定 `resetGroup`，指向现有父节点。引用及类型由 `parseMap` 校验；删除引用目标或选项会同时移除依赖配置与规则，编辑器可整体撤销。

| 扩展 | 格式与行为 |
| --- | --- |
| 对话结束事件 | `{type:"dialogue",source:对话ID或null,choiceId?:选项ID}`；限定选项必须同时指定对话；只有读完／选择后发送 |
| 目标变化事件 | `{type:"objective",source:目标ID或null}`；状态实际变化后发送，初始值不发送 |
| 已读条件 | `{kind:"dialogue",dialogueId,seen:boolean}` |
| 目标条件 | `{kind:"objective",objectiveId,status:"hidden"或"active"或"done"}` |
| 对话动作 | `{kind:"dialogue",dialogueId}`；排队并等待该次对话结束 |
| 目标动作 | `{kind:"objective",objectiveId,status}`；立即设置状态 |

选项条件与规则共用嵌套条件语义，显示与提交时均重新检查；选中有效选项后发送对话结束事件和可选信号。选项不可用时禁用，全部不可用时允许结束但不发送选项信号。已读记录在结束时写入，选择结果保存该段对话最近一次有效选择。可将信号接到另一段对话或变量、状态、阶段动作，不需要新增脚本。

对话队列为 FIFO，最多 32 项。当前行走段、传送、组动画、角色所乘平台行程与阶段镜头结束后才显示；清除尚未行走的路线。显示期间冻结模拟时间、等待任务和平台，禁止走路、机关与镜头交互。读完后继续后续动作；出口上的收尾对话全部结束后才判定通关。打开旅途手记同样暂停模拟。

最多 64 段对话、32 个目标，每段 1～32 句台词，每句不超过 300 字；说话者不超过 60 字，每段最多 4 个选项，选项文本不超过 60 字。剧情 JSON 长度限制为 150000 字符，最多 6000 种不同字符，以约束 GUI 字体图集内存。GUI 长正文按可用空间分页。

检查点增加目标状态、已读对话、最近选项、对话队列和当前台词下标，恢复后继续等待的剧情动作。局部重置清除归属该区域的对话记录、选择及排队项，恢复区域目标初值，并取消依赖这些剧情内容的未完成动作；全局剧情保持。调试暂停状态、事件日志、连通预览与手记的阅读页不写入地图或检查点。示例：`../maps/story-garden.json`。

## 试玩诊断

`inspectNavigation` 使用实际寻路的当前表面图，返回每个面的可达状态、路径／传送边、出口与门状态；无法推断未来机关姿态是否可解。规则诊断提供当前条件树和事件发生时的条件快照，最多保留 80 条事件及 20 条规则判断记录。暂停、单步、变量覆盖与信号注入只作用于当前运行实例；修改变量依旧校验类型和数值范围，事件在后续 tick 处理。导航分析仅在面板或预览开启时执行，并按姿态／镜头缓存；未变化的预览复用 SVG。
