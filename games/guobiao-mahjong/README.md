# 国标雀局 · Mahjong AI Arena

使用 Haiyue WebGPU 引擎 `Render3DSystem` 渲染牌桌、手牌、牌墙和牌河，HUD 与弹窗使用原生 `GuiSystem`。没有 HTML 游戏界面。

```sh
npm install
npm run build:target -- game:guobiao-mahjong
# 用本地 HTTP 服务打开 games/guobiao-mahjong/index.html
# 大厅入口：?game=guobiao-mahjong
```

点击右上角菜单打开原生 GUI 设置抽屉，选择东、南、西、北任一固定座位参与人机对战，或选择“四家 AI · 观战”。底部中央播放图标开始/继续，运行后切换为暂停；右侧为单步，左侧灯泡打开策略分析日志。P / 空格切换暂停，H 打开分析。
手牌点击一次选中，再次点击打出。裁判允许时，桌前直接显示可点击的大字“吃 / 碰 / 杠 / 胡”，同一行可选择“过”。吃牌打开牌面组合面板，每一组都是完整合法动作，金色边框标明吃入的那张；有多个杠牌选项时同样用牌面选择，关闭或重置会取消未提交的组合。
所有牌面、花牌与牌背使用同一张 `assets/tiles-atlas.png`，由引擎 3D 材质按 UV 取图。
各家的花牌、副露与剩余手牌沿同一条桌边对齐，花牌在最左侧，副露分组随后；摸到的牌单独排在手牌最右侧，并保留较大的间距；其余牌继续按花色与序数排序。
吃、碰、杠各为独立一组，组间留白；可吃碰杠的手牌高亮，副露中来自他家的牌单独用金色标明。
实体方桌采用 30° 斜俯视透视相机。常规桌面视口中，牌桌比之前扩大 15%，面板关闭时居中；打开左右抽屉时在宽屏为面板让出空间，窄屏以遮罩覆盖，矮屏内容可以滚动，并为底部播放器留出空间，避免挡住手牌。仍以屏幕高度的 95% 为取景上限；空间不足时拉远相机，保持完整牌桌可见。牌厚度为 15 个世界单位，玉色牌底占三成，配合接触阴影；牌墙层高和摸牌起点使用同一厚度参数。四家手牌立起，点击区域使用同一相机的透视投影。人机对战中其余三家的暗手保持 90° 垂直；观战明牌保留便于查看牌面的角度。
桌布使用生成的翡翠绿织物与金色回纹边框。中央四象圆徽表示风圈：东为青龙、南为朱雀、西为白虎、北为玄武；四方门风与“庄”印一起印在桌布表面，行动方以金色高亮。中央风圈和风向标记没有 GUI 控件或浮起的面板，标记随观察座位和庄家转动。四家牌河向外移，保留中央空区；牌墙同步外移，避免牌河与牌墙挤在一起。
余牌以四边两层牌墙显示，每边最多 18 墩；正常摸牌与补花、补杠分别消耗牌墙前后两端，单张残墩落在下层。牌墙展示不包含未摸牌的牌面信息。
牌墙按[麻将竞赛规则 2021](https://www.mindmahjong.com/adobe/MCR2021.pdf)的顺时针方向连续取牌，行牌座次仍为逆时针；前后两端都从现存牌墩的上层取牌。
摸牌、补花和出牌使用抛物线移动；吃、碰、明杠、暗杠、加杠把实际用牌移入对应副露，杠后的补牌在副露落定后起飞。胡牌时和张移到赢家手牌，赢家手牌展开；自摸的和张也会抬起归位。
正常自动对局在本次动画结束后继续，AI 计算后等待时间单独生效。暂停会冻结正在播放的动画；单步播放该步动画后保持暂停。切换座位、重置、读档和换局会清除旧动画。牌体使用引擎 `createRoundedBox3D` 的圆角立方体和平滑法线，静止与移动牌体合成一个 `InstancedPbrMaterial` 实例批次；飞牌只更新自身矩阵范围。牌面使用 PBR 合图材质，法线贴图按线性数据采样，轻微刻纹配合低金属度与清漆反光。静止与飞牌共享同一套颜色、法线贴图与材质，避免重新上传而短暂白牌。
四家 AI 观战时实时亮出全部手牌；人机对战中保留对手暗手。和牌或流局后，四家剩余手牌全部正面朝上摊平，副露与暗杠一同公开；下一局重新立牌。
观战明牌仅用于展示，传给内置与外部 AI 的决策观测仍按各自座位保密。
牌面采用用户提供图片，已去除右下角水印；`reference-tiles-clean.png` 为清理后的源图。
`pack-reference-atlas.mjs` 将 34 种牌面与已有八花、牌背合并为 43 帧 atlas，来源及编辑提示词见 `tiles-atlas.provenance.json`。
新增桌布、四象与法线素材由内置 imagegen 生成，文件与完整提示词见 `assets/table-materials.provenance.json`。桌布和所有中央图案在启动时合为一张材质合图，换风圈、门风或行动方仅更新 UV，不重传整张纹理。

当前番型位于画面底部，点击“番型明细”查看组成。左上角排名图标打开本场排名抽屉；右上角设置抽屉内提供座位、AI 模型、导出回放、计算后等待时间、牌局记录和“新比赛”。一局结束时，中央显示结算和“下一局”，四圈结束后中央按钮打开排名。

界面使用生成的墨绿金色背景、九宫格面板底图和透明排名图标；原图、校验值与完整生成提示词位于 `assets/ui-art.provenance.json`。背景和主 HUD 分别绑定各自的 GuiRoot，背景在 3D 之前绘制，不会重复渲染主 HUD。

番型说明：

- 未和牌时，显示已识别牌张与现有面子的**参考番数**，包括五门齐（6 番）及常见花色、范围、刻杠与顺子组合；这不是完整和牌的 81 番最终结算。
- 听牌时，用完整算番器枚举现有可见余牌的点和结果，显示番数范围；需要先弃牌的会注明“打某牌后”。自摸及其他特殊和牌条件另计。
- 当前能够组成和牌时，显示完整裁判的准确番数及距离 8 番门槛的差额。
- 未吃、碰或明杠时，已有番型包括门前清 2 番参考；暗杠保留门清，明副露取消。门前清按点和参考，自摸以完整裁判的不求人及不重复计分规则结算。
- 已有番型按手牌及副露一起判定无字 1 番；包含字牌时取消，清一色等按不重复计分规则排除。侧栏摘要保留无字，完整项目见番型明细。
- 花牌以实际花牌贴图单独显示，不计入起胡番数。

番型明细使用引擎 GuiModal，阻挡底层输入；打开时暂停行牌，关闭后恢复先前状态。
可以吃、碰、杠、胡时直接显示原生 GUI 大字操作，不再显示黄色机会提示条或下方重复的小按钮。
四家的实际吃、碰、明杠、暗杠、加杠、胡牌均弹出通知，并在动作所在方位显示大字淡入淡出效果。
通知按动作类型使用不同颜色，胡牌使用金色并优先提示；暗杠不会在通知中公开牌面。
快速连续动作的通知队列有上限，方位效果立即触发；新比赛、切换视角和恢复存档会清除旧通知。

番型分析在麻将 Worker 中运行；展示和排序不改变裁判手牌、合法动作或 AI 决策。
P / 空格暂停，H 打开策略分析。支持引擎 GUI 手柄指针。

底部滑条设置 **AI 完成计算之后** 的等待时间（0–5 秒）；公共接口可设 0–30 秒。
暂停会冻结等待时间，“单步”执行一个决策。“下一局”进入下一盘。
共 **东南西北四圈、每圈四局，16 局**，每盘更换庄家，流局也轮转，不设连庄。
累计和牌番数（含花）为主排名，同时展示标准零和比赛分、胜局数；同番按比赛分排序。

144 张牌含八花，自动补花，支持吃、碰、明杠、暗杠、加杠、抢杠和、杠上开花、绝张、海底。
**不含花牌至少 8 番才能和牌**。标准 81 番种及不重复计分由完整 MIT 算番库处理，
另支持库中“明暗杠”的组合调整。多人同时和牌取从放铳者起最近的一家，和优先于碰杠、碰杠优先于吃。
自摸三家各付 8 + 番花总分；点和由放铳家付 8 + 番花总分，另外两家各付 8。
自动存档使用引擎 Save 服务；恢复时重放每个动作并重新验证，恢复后先暂停。
外部模型的座位在恢复后需要重新接入；未接入时会保持暂停，不会悄悄换成内置算法。

内置 AI 在专用 Worker 内进行所有和型的精确向听分析、剩余有效进张、8 番有效听牌检验、
番型价值估计、两层进张搜索和基于公共牌面的防守。国标没有振听，弃牌只作风险信号。
它是有搜索的启发式算法。已完成与接入 KD 模型的固定牌山比较：这批测试中 KD 优于改前内置算法，具体数据与适用范围见 [强度比较](benchmarks/README.md)。不能据此宣称任一策略在所有对手阵容中最强。

完整强度比较工具位于 [benchmarks/](benchmarks/README.md)：固定牌山、四次换座、完整 16 局、按座位与局数归一化统计，另有独立验证集。模型故障会使评测停止，不会用默认弃牌掩盖问题；仅统计真实选择的耗时。原始回放、逐手番数和源码指纹保存在结果目录，可用 `benchmarks/archive.mjs` 保留对应版本源码。模型服务的 NumPy CPU 延迟与浏览器 WebGPU 延迟应分开看。

## 策略分析与持续日志

点击底部灯泡、按 H，或在右侧设置抽屉选择“策略分析”。日志框使用引擎原生 GUI，不暂停牌局，打开时仍能选择和打出手牌；宽屏会为日志让出位置，关闭后牌桌重新居中。

分析默认随公开局面变化自动更新，内容包括推荐动作及原因、备选出牌的向听/未见进张/相对风险、可追求的番型和补番条件、对手可能的路线与证据、应防的牌，以及未来最多六次自摸的试算。保留最近 400 条日志，可翻看历史、恢复跟随最新、清空或导出 JSON；换座位、读档和新比赛会清除旧视角日志，正常换局保留。支持关闭自动分析和单次刷新，可切换标准 64 路或精细 192 路抽样。

独立分析 Worker 复用国标 WASM 算番器，逐一检查 8 番起胡，花牌不用于凑门槛。分析只接收当前座位的手牌及公开信息：观战时也不会读取其他三家的明牌展示、牌墙顺序或裁判随机种子。旧局面任务可取消，迟到结果会被丢弃，不与对战 AI 共用计算队列。

概率需要按标注理解：固定听口用不放回抽样公式计算条件概率；其他局面用低向听策略抽样，并显示样本数和 95% 区间。“补齐关键牌”仅指路线所缺的关键牌，不等于已经胡牌；番型出现率可以重叠。试算假设未知牌等可能，忽略对手抢先和、后续吃碰和补花，不能当作整局胜率。未见进张也可能位于对手暗手，不能当作牌墙实存。对手牌型属于推测，风险分是相对指标而非放铳概率；国标没有振听，舍过的牌仍可能点和。

公共接口可供第三方策略面板或 AI Agent 读取：

```js
const coach = window.haiyueMahjong.coach;
coach.refresh();                  // 对当前可见局面重新分析
coach.snapshot();                 // 报告、建议、番型、对手推测和日志的副本
coach.exportLog();                // haiyue.mcr.coach-log/1
coach.setSamples(192);            // 16–256 路抽样
coach.setEnabled(false);          // 停止自动分析并释放分析 Worker
```

纯分析入口 `ai/coaching/forecast.ts` 的 `analyzePosition(observation, scorer, options)` 可独立复用；报告协议为 `haiyue.mcr.coach/1`，与执行动作的对战模型接口分离，不会自动代替玩家出牌。

## 接入第三方算法 / 大模型

页面提供 `window.haiyueMahjong`；渲染与裁判完全独立。例：

```js
const arena = window.haiyueMahjong;
arena.controller.setHuman(null);
arena.controller.setAgent(0, arena.httpAgent('模型 A', 'http://127.0.0.1:8765/agent/model-a'));
arena.controller.setAgent(1, {
  name: '自定义算法',
  async decide(observation, { signal, requestId }) {
    // 在合法动作集合中选择，必要时调用第三方服务。
    return observation.legalActions.find(a => a.type === 'hu')
      ?? observation.legalActions.find(a => a.type === 'pass')
      ?? observation.legalActions[0];
  },
});
arena.controller.setDelay(2000);
arena.controller.timeoutMs = 60000;
arena.controller.depth = 2; // 内置 AI：1 快速，2 两层搜索（默认）
arena.controller.autoNext = true;
arena.controller.start();
```

HTTP 端点收到 POST：

```json
{"protocol":"haiyue.mcr/1","requestId":"对局:决策:座位","observation":{"revision":0,"seat":0,"hand":[0,1,2],"legalActions":[{"type":"discard","tile":0}]}}
```

上面仅缩写展示字段。完整观测包含自己的手牌、各家手牌张数、公开副露/花牌/弃牌、当前舍牌、
圈风门风、剩余牌数、当前盘公开事件、之前各盘结果和合法动作；
**不含牌墙顺序、随机数状态、对手手牌、对手暗杠牌面、其他家的未决选择**。
`revision` 随每次有效决策递增。接口返回同一请求号、同一版本，并原样选择合法动作：

```json
{"requestId":"对局:决策:座位","revision":0,"action":{"type":"discard","tile":0}}
```

牌号：0–8 一至九万，9–17 一至九条，18–26 一至九筒，27–30 东南西北，31 中、32 发、33 白；
34–41 春夏秋冬梅兰竹菊。动作包括 `discard/chow/pung/kong/concealed-kong/add-kong/hu/pass`。
`chow` 必须保留完整 `tiles` 数组。观测的动作已经过裁判验证，大模型不需要自行声明和牌番种。
HTTP 返回错误、超时、版本不符或非法动作时，交互对局暂停并显示原因；不会暗中替换模型决策。
`setAgent(seat, null)` 恢复内置 AI；`controller.observation(seat)` 供裁判端调试，
参赛算法仅应使用传入的观测。JavaScript 插件属于受信任代码，不是恶意代码隔离环境。

`api/model-proxy.mjs` 提供能直接调用 chat/completions 兼容服务的大模型代理，密钥仅从服务端环境变量读取。
创建本地 `providers.json`（不要写入密钥）：

```json
{
  "model-a": {"endpoint":"https://provider.example/v1/chat/completions","model":"your-model-name","keyEnv":"MODEL_A_KEY","jsonMode":true},
  "model-b": {"endpoint":"https://provider.example/v1/chat/completions","model":"another-model","keyEnv":"MODEL_B_KEY","jsonMode":false}
}
```

```sh
node --experimental-strip-types games/guobiao-mahjong/api/model-proxy.mjs /path/to/providers.json
```

代理只监听本机，仅允许本机页面跨域访问；需要服务支持相应 JSON 返回格式。
可从 `arena.systemPrompt` 取得规则提示词，从 `arena.fanCatalog` 取得完整番种目录。

## 批量比赛与复盘

```sh
node --experimental-strip-types games/guobiao-mahjong/api/arena.mjs games/guobiao-mahjong/api/arena.example.json /tmp/mahjong-results.json
```

配置可混合内置算法与 HTTP 算法。默认同一 seed 轮换四次座位，每次完整 16 局，减小座次和牌运偏差。
结果包含排名、番数、比赛分、胜局、故障次数和每局详情。无界面比赛无展示等待；
超时/非法返回记录 `faults` 并执行过牌或首个合法动作，比较模型时必须同时检查故障数。
也可直接导入 `api/tournament.ts` 的 `runTournament`，传入四个 `MahjongAgent`，支持取消和事件回调。强度评测应设置 `{ strict: true, skipForced: true }`：模型异常立即停止，仅有一个合法动作时直接执行。CLI `arena.mjs` 默认开启这两项；需要测试旧版容错行为时，可在配置中显式设为 `false`。
批量场景的内置算法可同步运行；浏览器交互对局使用 Worker。

“导出回放”包含 seed、原始动作、公共事件及结果；可用 `rules/replay.ts` 的 `replayMatch` 重新裁判。
完整回放属于裁判数据，会暴露随机种子及暗杠，不应在对局中提供给参赛模型。

```sh
node --experimental-strip-types --test games/test/guobiao-mahjong.test.mjs games/test/guobiao-mahjong-presentation.test.mjs
node games/guobiao-mahjong/verify-browser.mjs
node games/guobiao-mahjong/verify-performance.mjs after
```

测试覆盖 214 个原生 C++ 算番回归样例、番花门槛、牌张守恒、抢杠、优先级、四圈、
信息隔离、可调等待、暂停/单步及无界面比赛。浏览器脚本检查真实 GUI 点击、后台决策、暂停和竖屏布局。
源码与许可见 [第三方声明](THIRD_PARTY_NOTICES.md)。

性能脚本在固定浏览器尺寸和种子下，测量静止牌局、后期牌局及录制动作驱动的自动对局，将帧间隔、长任务和 CPU 采样保存到 `artifacts/guobiao-mahjong/performance/`。HUD 只在牌局或观测座位变化时重新获取观测；只有能点击的手牌创建 GUI 输入控件；3D 投影随窗口和牌位变化失效，网格缓冲区按实体牌数及最多 32 张飞牌分配。

未连接手柄时仅轮询设备，跳过四个空槽的模拟快照及哈希；同帧采样与连接提示复用一次设备读取。桌面文字只应用最终字号，布局在视口变化时更新。动画历史只保存上一帧牌位、牌墙游标和必要公共字段；通知只处理新增事件。网格复用顶点及索引存储，牌体仅发布有效顶点，每个面体只计算一次旋转基；规则响应没有改变牌面时不重建网格。`snapshot()` 每次只获取一份牌局观测。

性能报告同时记录实际 `GPUQueue.writeBuffer` 次数/字节数、每帧脚本耗时和规则进度，避免把更多已执行动作误判为回退。队列写入量不代表 GPU 执行时间；`presentation.scene.work` 提供网格重建、提交次数及几何发布字节计数。

## 浏览器预训练模型（Worker + WASM / WebGPU）

点击原生 GUI **AI 模型**，可直接选择三个 MIT 国标 KD Student 或 KD Ensemble 3，按座位混用。浏览器推理无需 Python 或容器，TensorFlow.js 4.22.0 在专用 Worker 内运行。**WebGPU 加速默认开启**；同一菜单可切换 WASM CPU。WebGPU 初始化不可用时，界面明确提示使用 WASM，继续运行同一份模型；加载、校验或推理失败会暂停并显示原因。

四家共用一个 Worker，最多缓存三个 checkpoint；集成模型复用同一批权重。切换后端会终止旧 Worker 并释放张量。单模型首次需约 26.6 MB，三模型约 79.7 MB；仅在选择模型后按需加载，下载进度可见，关闭菜单可取消。权重固定版本与 SHA-256 校验，验证后存入浏览器 CacheStorage；无持久缓存权限时仍可运行，之后可能重新下载。

构建自动复制 TensorFlow.js 的 JS/WASM 文件，并优先分发已下载且校验通过的本地权重；缺少本地权重时，浏览器从固定版本的 Hugging Face 地址下载。准备可离线分发的资源：

```sh
npm run models:fetch --workspace @haiyue/game-guobiao-mahjong
npm run build --workspace @haiyue/game-guobiao-mahjong
```

普通静态服务器即可运行，WASM 使用单线程 SIMD，不要求 COOP/COEP。WebGPU 需要浏览器与安全上下文支持。模型分配、加速后端、温度、种子随自动存档恢复；刷新页面后 HTTP 模型仍需重新连接。温度 0 取合法动作中的最大概率；集成取各学生合法 softmax 概率的平均。正温度使用浏览器端确定性随机数，同一牌局、版本与种子可复现，但随机序列不与 Python 的 NumPy PCG64 保持一致。

对第三方算法，原有 `MahjongAgent` 接口仍适用。也可直接调用浏览器模型：

```js
const hub = window.haiyueMahjong.modelHub;
const request = new AbortController(), signal = request.signal;
const observation = window.haiyueMahjong.controller.observation();
await hub.prepare(['builtin', 'browser-kd-s0', 'browser-kd-s1', 'browser-kdens3'], 'webgpu', signal);
hub.apply(['builtin', 'browser-kd-s0', 'browser-kd-s1', 'browser-kdens3'], { temperature: 0, seed: 42 }, 'webgpu');
const action = await hub.browserAgent('browser-kd-s0').decide(observation, { signal, requestId: 'comparison-1' });
const diagnostics = hub.snapshot().browser; // 实际后端、缓存、推理时间和张量数
const saved = window.haiyueMahjong.save();
await window.haiyueMahjong.restore(saved);
```

模型只接收当前座位的公共观测，所有输出重新通过合法动作及版本校验。原 NumPy 模型的 CHW 展平顺序、FP16 权重转置和 235 动作编码保留；测试使用固定 NumPy 参考数据核对 12 种实际观测。

```sh
node games/guobiao-mahjong/verify-browser-models.mjs
```

浏览器检查原生菜单、两种真实后端、集成、缓存共享、取消/重启/存档、稳定张量数，以及推理与 3D 牌桌同时运行的帧间隔。结果在 `artifacts/guobiao-mahjong/browser-models/`，这是当前设备的诊断数据，不代表模型对局强度评测。

原有本机模型服务和大模型代理继续可用，原生 GUI **AI 模型** 中填写服务地址并连接后即可切换。模型来源、Docker Compose、公共接口与适配差异见 [模型服务说明](model-service/README.md)。

### 末张防守增强

内置 AI 及策略分析已增加末张防守：牌墙耗尽、自己不能胡牌时，优先打仅凭公开牌即可确认不会放铳的牌，并在分析日志解释原因。判断包含国标特殊牌型，不读取对手暗手。模型菜单可选择 **浏览器 · KD 0 + 末张防守**，复用原来的 KD 0 权重；WebGPU 默认开启，可切换 WASM，也支持存档恢复。普通巡次不额外搜索或增加模型计算。

第三方模型也可使用同一防守接口：

```ts
import {withLastTileDefense} from './api/defensiveAgent';
const defended = withLastTileDefense(yourAgent);
game.setAgent(1, defended);
```

本次还测试了 KD 加有限搜索，开发对局未显示稳定提升，保持实验状态。末张防守在 1792 局旧牌谱中找到 9 次可避免的实际放铳；这是反事实核验，不是整体胜率提升幅度。完整实验与复现方式见 [benchmarks/README.md](benchmarks/README.md)。

### 学习评分与目标成牌搜索

AI 模型菜单新增 **KD 0 + 策略学习（实验）**。它复用 KD 0 策略先验，在有接近的备选弃牌时，利用独立训练的小模型比较弃后向听、有效进张、合法八番听口、有限成牌路径、弃牌时序、余牌量和累计番差。每次最多比较三张弃牌；KD 先验明显时直接返回。学习评分仅在温度 0 生效；其他温度保留原策略采样及末张防守。原有 KD 模型和内置算法仍可选择。

分析日志新增：

- **模型风险估计**：分别估计三家当前能否点和这张牌。不是整局放铳率，也不能把三家的概率相加当成联合概率。
- **目标成牌搜索**：从候选弃牌出发，搜索最多两次进张的改善路径；所有返回成牌都由现有国标裁判核验不含花达到八番。显示所需牌、自摸/点和番数及补齐所需牌的条件概率。搜索有固定预算，路线可重叠，未找到路线不能证明无成和机会。

两个小模型合计约 18 KB，在 Worker 内运行。训练风险标签使用牌谱的完整裁判状态，在线输入只读取己方手牌和公开信息。训练、校准和离线测试按原始牌山 seed 分开，包括同 seed 的全部座位轮换。

开发、验证与复现说明见 [benchmarks/README.md](benchmarks/README.md)。实验模式是否成为默认由独立对局证据决定，模型预测准确率本身不作为棋力提升结论。

### 候选模拟与行动价值

模型菜单中的 **实验 · KD0 蒸馏价值** 使用 KD 0 提供候选先验，再由三个学生价值头比较行动收益。除前三个候选弃牌外，覆盖过、所有合法吃法、碰、明杠、暗杠和加杠；每种吃碰最多比较两张后续弃牌。价值评分确认的吃碰组合会记住配套弃牌，仅在实际副露后的公开状态完全吻合时执行；被胡牌或更高优先级响应抢先时不会误用。没有确认组合优势时保留 KD 的吃碰选择，后续弃牌重新由 KD 提供先验，不强制使用形状启发式方案。

训练标签来自候选动作的完整单局模拟：同一局面、同一组未知手牌和牌墙，分别执行每条行动分支，再由四家按冻结策略打到胡牌或流局。裁判共用游戏的补花、吃碰优先级、抢杠和不含花八番门槛。标签是实际模拟得到的己方番数、其他三家平均番数、和牌与放铳结果，不使用“照抄获胜牌谱中的动作”作为价值目标。

浏览器只运行小网络和必要的规则评估，不运行训练或完整单局模拟。KD 主网络仍使用现有 Worker 和默认 WebGPU，也可切换 WASM；学生价值头在同一 Worker 内计算。三个网络对备选动作意见不一致、收益优势不足或原策略支持过低时保留原选择；合法胡牌和末张防守优先。温度大于零时使用原 KD 采样与末张防守。

当前价值目标是**本局预期己方番数减其他三家平均番数**。未知牌只按公开牌张守恒均匀抽样，尚未学习对手暗手分布；后续四家使用冻结的内置 depth=1 策略。因此模拟价值有分布偏差，也不代表整场剩余局数的最终名次概率。该模型保持单独实验选项，实战强度须看独立牌墙对局。

蒸馏前 v1 的历史 512 局验证中，价值版累计番数为 3.588 番/局，同桌 KD-safe 为 3.245；差值的 95% 区间为 [-0.139, 0.870]，尚不能确认稳定提强。平均比赛名次为 2.313，对照 2.563。这组历史结果对应原始价值网络，不能直接作为当前蒸馏学生的成绩。数据来源与限制见 [v1 评测记录](benchmarks/value-results-20261107.json)。

### 离线教师与浏览器学生

大计算量的模拟和训练通过 `benchmarks/` 中的离线工具执行：完整对局模拟生成标签，三个 194→128→4 的教师网络学习价值，再用教师软价值、候选策略分布和真实模拟标签联合蒸馏三个 194→16→4 的学生网络。教师只使用公共特征；对手暗手和未来牌墙不会成为在线输入。

学生有 9564 个参数，为教师的八分之一；FP16 权重与共享 FP32 归一化数据合计 20680 字节，完整导出模块约 31 KB。游戏的推理 Worker 脚本由约 569 KB 降到 161 KB。**本次压缩的是新增价值头，KD 主干仍使用原来的约 26.6 MB 权重。** 浏览器不加载教师、优化器、训练数据或整局模拟器；源码依赖检查和构建检查会阻止这些内容进入游戏入口。

离线测试集上，量化学生与教师的候选选择一致率为 96.35%。保真率不是棋力提升证明，实战单独比较上版价值网络。使用时在 AI 模型中选择 **实验 · KD0 蒸馏价值**，温度设为 **0**，模型 ID 为 `browser-kd-s0-distilled`。

原版 **实验 · KD0 行动价值**（`browser-kd-s0-value`）继续保留，已有存档仍恢复原模型。其约 424 KB 的 JSON 权重只在选用原版时加载，并校验长度与 SHA-256；紧凑模式不加载这份数据，两种模型仍共用同一个 KD 推理 Worker。512 局对照中，学生为 3.354 番/局，原版为 3.672；因此没有用学生替换原版，只提供单独的实验选项。详见 [蒸馏评测记录](benchmarks/distillation-results-20261107.json)。

```sh
# 在 Games 目录执行；复用已有模拟数据，不在浏览器重新模拟或训练
node games/guobiao-mahjong/benchmarks/distill.mjs artifacts/guobiao-mahjong/value/data-v2 artifacts/guobiao-mahjong/distillation/model-v1
npm run build --workspace @haiyue/game-guobiao-mahjong
```

流水线先归档并校验数据来源，再训练教师与学生；校准和特征核验通过后才导出学生。`MAHJONG_PYTHON` 可指定已有 Python 环境；`--export-only` 可跳过训练，校验并导出已经训练好的模型。配置、格式与复现说明见 [离线蒸馏说明](benchmarks/README.md)。

### 教师独立评测与强策略模拟

离线工具新增四版本对照：原版价值头、较大教师、未量化 FP32 学生和实际部署的 FP16 学生。三个候选分别对阵三家原版，使用相同牌墙、四座轮换；记录改选动作及弃牌、吃碰杠后的本局结果。教师通过独立实战门槛后，才考虑下一次学生发布；候选一致率仅用于定位压缩损失。

本轮 1536 局中，教师为 3.473 番/局，同桌原版 3.633，尚未通过提强门槛；FP32 与 FP16 学生的 512 局配对轨迹和结算完全一致，未观察到量化的额外损失。后续优先改进标签与教师训练，详见 [四版本评测记录](benchmarks/teacher-ablation-results-20261107.json)。

模拟标签可改用 KD0 与原版价值模型的混合续局策略。预算按 8、32、64、128 个公共信息一致的未知世界递增；吃碰杠与高风险弃牌至少 32 次，候选接近时继续加算。每个候选共用相同世界和座位策略，每条分支隔离续牌记忆；输出可恢复的分片和加算原因。教师、模拟器及标注工具仍只在离线入口运行。命令和结果见 [教师评测与自适应标注](benchmarks/README.md#教师独立评测与强策略标签)。

### 对手推断与整场联合学习

AI 模型菜单新增 **实验 · KD0 联合候选**（`browser-kd-s0-joint`），可给任意 AI 座位单独选择。它复用 KD0 主干，通过公开弃牌时序、副露、余牌及分差推断对手听牌与危险牌，再对全部合法弃牌、每种吃碰及其后续弃牌、各类杠联合选择。确认的吃碰续牌在公开状态吻合时执行，合法胡牌及末张防守仍优先。温度 0 选择最高概率动作，非零温度按联合策略采样，采样随机源由种子和当前局面固定。

新增对手网络与联合学生网络合计 35928 字节网络数据，完整按需资源 57055 字节；KD0 主干大小保持原样。两个小网络在已有推理 Worker 内计算，KD 主干默认 WebGPU，可切换 WASM，WebGPU 不可用时明确回退。教师、训练器、未知世界模拟与自博弈联赛都放在线下。

本轮实际训练包含两代联赛、32 场完整比赛、512 局、1024 个抽样决策和 108680 次合法行动。对手网络在按原始牌墙留出的测试集上，听牌 Brier 为 0.086，常数基线为 0.112；这些预测指标不代表实战胜率。模型还使用了 1920 个低权重旧局面与 9 个全动作扩展搜索局面。当前是小规模训练闭环，扩展标签和整场训练量仍需继续增加。

联合策略教师同时学习本局与整场剩余番数、和牌、放铳及夺冠辅助价值。整场主目标为剩余己方累计番数减其余三家平均番数，夺冠奖励权重为 0.2。联赛保留 KD0、原版价值、所有历史联合版本和进攻、防守风格；更难的对手获得更高采样权重。学生离线测试的动作计划一致率为 98.96%，保真率与独立棋力评测分别记录。

`BrowserModelRuntime.policy('browser-kd-s0-joint', ...)` 返回最终合法父动作概率；已确认的吃碰续牌和规则保护返回确定性分布。同一次推理的原始 KD 先验由 `priorProbabilities` 返回，方便对照原始建议与最终选择；原始 KD 模型也可通过 `browser-kd-s0` 单独查询。具体输入仍为 `Observation` 公共观测，第三方算法无需获得其他三家的暗手。批量原始 KD 推理继续使用原接口。

训练、导出、逐手回放验证和独立对照见 [联合学习与联赛说明](benchmarks/README.md#对手推断联合动作学习与整场联赛)。原版算法与之前的实验模型继续保留，实验候选不会自动替换已有配置。

本轮用四个全新牌墙、四座轮换完成 32 场独立比赛、512 局。教师平均 2.609 番/局，同桌原版 3.799；实际 FP16 学生为 2.859，同桌原版 3.712。两者均未通过提强门槛，当前测试表现弱于原版，因此保留为独立实验选项。逐手合法回放和 93677 次行动的结算核验通过，零算法故障、零漏胡。结果见 [联合学习评测记录](benchmarks/league-results-20261107.json)。
