# 候选去冗余与增量唯一性验证

2026-09-20。仅修改数独模型和对应诊断，未修改引擎。

## 不等号为什么会漏删

旧版只专门删除“两端都是已知数”“较小端给定 1”“较大端给定 9”。后续全局删符号有搜索预算，并保护第一个符号。因此有些靠行、列、宫即可判断的冗余符号仍然保留。

截图的最小回归：R1C4=1、R3C5=2。暂时去掉 R3C5 < R2C5 后，R2C5 候选仍为 3～9，因此该符号不提供信息，必须删除。若去掉已知的 1，R2C5 又可能为 1，则保留符号。

从 iPhone 诊断快照获取实际题目种子 3201254713（标准、关闭 LED、开启数比），用修改前后版本重新生成：已知数字完全相同，符号从 15 个减少到 10 个，R2C5 下方的符号消失，完整搜索仍唯一。对旧题直接做局部检查也能删除 3 个冗余符号。固定输入见 [player-seed.json](player-seed.json)，已加入回归测试。

新检查先移除待检符号，重新计算两端候选，再检查所有逆序/相等的组合是否可能同时合法。范围来自行列宫、LED、奇偶、和、路径等现有约束。另一条递增不等号路径或温度计路径也能证明冗余。逐条删除、逐条重建约束，避免循环论证，不读取答案；第一个或最后一个符号也不豁免。若选定规则全部消失，重新构造题目。XV/白点全标记及未标记边的负约束不变。

这是有边界的局部蕴含检查，之后仍保留有预算的全局删减，不宣称得到全局最少符号。删除其他约束只会放宽候选范围，因此不会使先前留下的局部有效符号变成局部冗余。

## 算法选择

成熟路线包括约束传播＋最少候选优先（MRV）搜索，参见 [Peter Norvig 的数独求解说明](https://www.norvig.com/sudoku.html)；以及将问题编码成精确覆盖后使用 Algorithm X / Dancing Links，参见 [Knuth 原论文](https://arxiv.org/abs/cs/0011047)。

本项目已有位掩码、MRV、结构缓存；不等号、和、温度计、缺格和全标记负约束需要额外处理。根据这些约束的结构，继续使用现有 CSP 求解器比直接整体换成精确覆盖更便于复用全部变体语义。这是本项目的工程判断，未实现完整 DLX 对照，不能据此声称 DLX 一定更慢。

实测过在分支前增加完整单元的隐性唯一数传播：节点减少，但部分复杂规则整体更慢，未保留该版本。

最终采用增量唯一性证明。设修改前题目 P 唯一，删掉单格线索 C 得到 Q，已知终盘仍满足 Q。任何新增解如果仍满足 C，也将是 P 的第二个解，矛盾。因此只需搜索 Q 且不满足 C：

- 删除已知数 v：该格只搜索非 v 的候选。
- 删除部分 LED：该格只搜索不匹配旧亮灯的候选。
- 若当前候选已经全部符合旧线索，直接证明唯一性保持。
- 否则搜索第一个反例；完整搜索无反例才接受，预算耗尽恢复线索。

该优化仅用于已知唯一题目的单格削弱。任意输入、批量删除符号和对外验证依旧完整搜索至最多两解。基础技巧难度门槛不变。

## 串行基准

同一 Mac / Node 24，六种配置各三个种子（39、20260920、20260921）。两轮分别 AB、BA 顺序，每版本独立 Node 进程；计时期间没有并行测试或构建。每个进程从空缓存开始，进程内后续样本复用摩天大楼表。表中每格平均六次生成，不是所有种子的性能保证，也不是手机耗时。

| 配置 | 修改前 | 修改后 | 平均耗时减少 |
| --- | ---: | ---: | ---: |
| 普通 LED | 17.3 ms | 11.9 ms | 31.1% |
| LED 挑战 | 77.4 ms | 51.1 ms | 34.0% |
| 经典挑战 | 189.2 ms | 142.4 ms | 24.7% |
| 四种高级规则挑战 | 1964.0 ms | 1861.1 ms | 5.2% |
| 杀手挑战 | 140.2 ms | 107.6 ms | 23.3% |
| 多规则挑战 | 438.1 ms | 366.1 ms | 16.4% |

高级规则组合的两轮差异较大（第一轮约快 11%，第二轮约慢 1%），不宣称该类题有稳定明显提速。详细原始数据、题目哈希及版本源文件哈希见 [benchmark.json](benchmark.json)。唯一解和挑战门槛的独立验证在计时外完成；优化前后题目不保证完全相同，同版本同种子仍确定。
