# 流光数独 / LED Sudoku

一个独立的 Haiyue 游戏，入口 `games/led-sudoku/index.html`，manifest ID `led-sudoku`。原 `sudoku` 游戏保持独立。

## 构建与启动

```sh
cd Games
npm run build:target -- game:led-sudoku
python3 -m http.server 8317 --bind 127.0.0.1
```

打开 http://127.0.0.1:8317/games/led-sudoku/ 。需要支持 WebGPU 的浏览器。本游戏使用 Haiyue `World`、`Camera3D`、`Mesh3D`、`BasicMaterial`、`Render3DSystem` 渲染灯管棋盘，DOM 承载响应式设置和可访问输入。`@haiyue/engine/experimental` 的公开 `RenderIntegration`、`requireEngineDevice` 依赖已在 manifest 标识。仅维护一张 1260² GPU 纹理，输入后重绘，销毁时释放纹理、世界、引擎、Worker、监听器与计时器。

构建产物包括 `bundle.js` 和 `generator.worker.js`；构建 runner 必须等两个文件都生成。主入口仅编译本游戏和引擎源码，Worker 单独用小范围 tsconfig 编译，避免出题 Worker 和小游戏构建重新检查全部游戏。`preview:build` 会复制 Worker、HTML 和 CSS。

## 玩法与规则

- 青色是不可改的完整已知数；琥珀色是可填写的局部灯段线索；绿色是玩家数字；红色表示错误。
- 亮灯段必须包含在答案中；暗灯段是未知，**不代表该段必须熄灭**。七段位序为上、右上、右下、下、左下、左上、中。中间段 `0x40` 排除 1、7。
- 候选数、单候选提示、完整单元的隐性唯一位置提示、推理解释、自动求解、三档难度、新局、自动存档均保留；新增笔记、撤销、擦除、键盘操作、LED 计时。灯管已取消辉光，暗段调为 `#162b33`。
- 点击“新数独”打开设置面板，选择三档难度和额外规则，点击“开始新数独”后生效；关闭面板不改变当前棋局。
- LED 灯管是默认开启的规则；关闭后使用普通数字和无灯段约束的唯一解题目。可以组合对角线、缺一门、杀手、连续数（升序/降序）、相邻连续（差 1）。
- 所有可填的 LED 格始终展示七段灯管，零亮段显示全暗灯管；缺一门黑格使用 ×，不显示灯管。
- 候选输入按钮按 1–9 九宫格排列；计时使用 LED 灯管数字。完成时棋盘边框缓慢闪烁四次后保持亮起，撤销完成或开始新局会恢复；减少动态效果设置下仅保持发光。
- 缺一门：每行、列、宫各有一个预设黑格。黑格不填，其余八格使用 1–9 且不重复，**不要求填齐 1–9，也不固定全盘缺同一个数**。隐性唯一位置只用于九个有效格的完整单元。
- 杀手：连通虚线笼内不重复，数字和等于笼左上角标注。笼覆盖全部非黑格，可与 LED 及少量完整已知数混合。
- 连续数：沿整条紫线每步差 1，可以全部升序或全部降序，不能乱序或中途转向。例如 2→3→4、4→3→2 合法，2→4→3 不合法。旧版 Renban 存档仍按顺序不限解释，并标明旧版；新开数独使用新规则。
- 相邻连续：白点两侧差 1；所有差 1 的边都标点，所以无点的相邻非黑格不能差 1。与紫线连续数是独立开关。
- 对角线与缺一门组合时仅要求对角线上可填格不重复。
- 数比：24 条相邻格大小关系，符号尖端指向较小的数字；未填的端点也会排除不可能的 1 或 9。与差 1 白点共用边界时，符号沿边界错开。
- 多对角线：三条带编号的金色虚线贯穿斜向格子，连接盘面边缘。每条线上的有效格不重复，短线不要求出现全部 1–9。斜线在终盘求解前生成，属于真实求解约束；缺一门黑格不参与。
- 排除点：交点圆圈影响周围四格。普通数字圆圈排除该数字；琥珀 LED 圆圈排除所有包含已亮灯段的数字，暗段未知。例如单独左上竖管排除 **4、5、6、8、9**，左上竖管加底横管排除 **5、6、8、9**。候选面板列出所选格涉及的实际排除集合。关闭 LED 后只生成普通数字排除点。生成时避开黑格和相邻圆圈。
- 奇偶：24 个带标记的格子，蓝底＋“偶”只允许 2、4、6、8，红底＋“奇”只允许 1、3、5、7、9，无标记不限制。
- 温度计：青绿粗管与圆灯泡，从灯泡到平头数字严格递增；候选会考虑尚未填入的中间格所需间隔。
- 摩天大楼：盘面外围四侧数字表示从该侧向内可见的楼数，高楼遮住后方低楼。行、列均用双侧线索进行精确可行性检查。
- XV：紫色矩形字母牌，V 代表相邻和 5、X 代表相邻和 10；所有符合的边都标出，无标记的边也排除和 5/10。
- 四数和：蓝色菱形 `Σ数字` 表示周围四格之和。四格可以出现行、列、宫允许的重复值。
- 组合限制：温度计与连续数、XV 与数比/差 1、四数和与排除点互斥以避免标记混淆；摩天大楼与缺一门互斥以保持完整九格序列。最后开启的规则优先，面板显示关闭原因。生成与存档校验也拒绝冲突组合。
- 显示答案需游戏内确认，并标记辅助完成；撤销答案后仍保留“使用过辅助”的记录。

规则资料：[2025 全国数独锦标赛题型说明（缺一门）](https://www.sport.gov.cn/stzx/n5434/c28838581/part/28838591.pdf)、[泰安市体育局比赛题型说明（对角线、杀手、连续）](https://tyj.taian.gov.cn/art/2024/11/16/art_45326_10298555.html)、[数独小栈 Renban 规则](https://variantsudoku.top/puzzles/70)。

## 生成与唯一性

`rules.ts` 为无平台依赖的确定性模型。由 seed 产生随机合法终盘，再生成黑格、连通杀手笼、连续升降路径和全标差 1 边。逐格移除完整已知数，替换为严格小于完整数字的灯段子集或空格。挖空在**全部有效规则和灯段约束**下使用增量唯一性证明：修改前已唯一，新增解必定违反刚删除的线索，因此只搜索该格中原线索不允许的数字；完整证明不存在新增解后才接受。普通求解和批量删符号仍使用最多两解的 MRV 搜索。

搜索预算耗尽会恢复刚移除的线索，绝不把未完成搜索当成唯一性证明。入门/标准保留原有密度目标；挑战以 17 个完整已知数为初始目标，随后按实际解题过程筛选，不以给定数数量替代难度。

`analyzeSingles` 只读取题面，使用与候选输入一致的 LED、附加规则约束，依次执行单格唯一候选和完整单元的唯一位置，不读取答案、不试探。挑战必须在两类技巧都耗尽后，仍有至少 `max(12, ceil(初始空格 / 4))` 个空格。挖空、削减亮灯后若仍过易则重新生成，最多八次；不会以简单题兜底冒充挑战。这是基础技巧下限，不是完整的高级技巧评级，也不承诺无需试探。

挑战的可选标记更稀疏（数比/奇偶各 12 个），杀手笼更大；摩天大楼每侧保留四个线索，空白表示不限制该方向可见数，存档以 0 表示省略，界面不显示数字 0。XV 和相邻连续的所有匹配边仍然全部标记，未标记边的负约束不变。摩天大楼排列使用位置/数字位集合加速。削减冗余线索时，完成且合法的全强制单数推演本身也是唯一解证明；出现推演停滞时仍须完成增量唯一性证明。

完整出题和难度评估在 Worker 内运行，失败或超时显示可重试错误，不回退到主线程计算。旧存档保持原题面，不会因算法升级改变玩家正在进行的棋局；新标准在开始新数独时生效。

数比符号先做候选范围去冗余，再做有预算的唯一解删减。每次暂时移除待检符号，以行、列、宫、LED 及已启用规则重新求两格候选；若不存在违反符号且同时合法的数字组合，或其他不等号/温度计已有递增路径，就删除该符号。检查逐条进行，不允许两个符号互相证明后一起消失；第一个符号也不会豁免。该检查不读取答案，不消耗回溯预算。详细依据、回归和性能数据见 [候选去冗余与增量验证](evidence/clue-pruning/README.md)。

生成性能优化：行、列、宫、对角线和短斜线的占用数字使用九位掩码，在递归赋值/回退时增量更新；LED、奇偶、排除点约束预先转换为候选掩码，先过滤再检查复杂规则。挖空和难度筛选各自复用结构上下文及摩天大楼可行性缓存，不为每次唯一解检查重建 81 格关系。缓存只在当前操作内复用，修改题面后不会读取旧结构。MRV 选格、候选顺序、搜索预算及挑战门槛不变；同一版本同种子保持确定性，算法升级前后的题面不保证完全相同。

可运行 `node --experimental-strip-types games/led-sudoku/benchmark.mjs [rules.ts路径] [输出.json]` 比较版本。基准使用六类配置、各三个固定种子；只测完整生成，另行验证唯一解和挑战门槛，并记录题面/解的 SHA-256 和搜索节点数。每个版本使用独立进程，从空缓存开始；后续样本会复用该进程的摩天大楼表，不能将其误作每题冷启动耗时。

`generator-client.ts` 使用带类型、版本和请求 ID 的专用 Worker 消息，替换新请求时取消旧请求，拒绝旧回包和重复回包。存档通过独立 `led-sudoku` 槽保存题目、解、笔记、进度、计时和辅助标记；恢复前校验结构与解的一致性。撤销历史仅在当前会话保留。

“推理解释”按步骤展示基础候选、具体单元、逐项排除依据和结论，支持前后翻页与棋盘同步高亮。数据来自当前规则，讲解不自动填数或改动笔记；原有存档无需重开即可使用。Native 提供中文、英语、日语。截图棋局的六步回归及范围说明见 [分步提示验证](evidence/hints/README.md)。

连续升降修正增加 `led-sudoku-ordered.test.mjs` 的 5 项检查，共 143 项专项测试。新题写入 `lineRule: ordered`，候选使用整条路径的两种方向及距离约束；旧存档缺省该字段时保留无序 Renban 语义。设置、当前规则和逐格说明同步更新。

当暂时无法直接填数时，提示会查找可减少候选的格子；解释按候选、规则依据、删减结果逐步展示，末页“应用到笔记”可记录结果并支持撤销和存档。支持区块排除、数对/三数组、X-Wing，以及不等号、温度计和连续升降序的候选约束。手写笔记不参与推理判定。

高级候选提示还支持 XV/相邻连续的正负标记配对、四数组、隐性数对/三数组、XY-Wing、XYZ-Wing 和有界候选推理链。链式提示逐页解释假设如何导致矛盾，再允许用户将实际排除写入笔记。缺门短区域不会套用完整九格区域的必填规则。

笔记交互：候选数字点击划去，再点恢复；盘面与数字键同步显示删除线，不再高亮手动候选。`crossed` 位掩码独立保存排除标记，旧存档 `notes` 不会被反向解释为排除。标记不参与求解证明，提示的“应用到笔记”也使用删除线；撤销、擦除、填数和重载保持一致。

完成盘面后，“答案”按钮禁用；撤销到未完成状态后恢复。完成瞬间播放一次约 2.2 秒的格子背景扫光，从左上角沿对角方向到右下角，不给数字添加辉光。载入已完成存档、普通重绘和回到前台不会重复播放；新局、撤销及离开前台会停止动画。

皮肤支持“深色流光”和“晴空浅蓝”，独立于棋局保存，切换不重置进度。Native 在齿轮设置的皮肤下拉框切换，支持中文、英文、日文；网页版在顶栏选择。浅蓝配色覆盖盘面、LED 暗段、候选笔记、规则标记、计时器与面板；浅色 UI 使用无色调压缩的场景输出，保留配色本身的明亮度。

额外区域：每块轮廓色块含 9 个格子，作为额外的宫约束 1–9 各出现一次。默认从偏移方宫、参考图不规则形状中选择四块四方旋转对称布局，字母 A/B/C/D 区分区域。不可与缺一门、奇偶底色叠加；候选、基础提示和高级推理共用额外宫约束。

不连续：上下左右相邻的可填格不能相差 1，斜角不受此规则限制；不添加棋盘符号，与白点连续、紫色连续线互斥。完整解构造使用位集合候选传播、邻格弧一致性、唯一位置传播和候选较少格优先搜索；题面仍走有预算的唯一解验证。与额外区域组合时，先构造有效完整解，再长出两块各 9 格的紧凑中心对称区域，避免强行匹配固定四宫模板带来的长时间搜索。笔记提示支持不连续候选配对和推理链。

### 小杀手数独

新数独面板可以启用小杀手：外围橙色数字与斜箭头表示从箭头入口至另一侧边缘的沿线总和。沿线数字不额外要求互异，仍服从行、列、宫及已启用规则。为保证手机边缘清晰，与摩天大楼、缺一门互斥。

生成使用可达和动态规划与候选区间剪枝，唯一解仍由有预算的搜索验证；删去全已填线索、已由完整九格区域确定的总和，并在预算内减少冗余箭头。求和提示支持候选排除、逐步说明、笔记应用和中英日文。网页、Native 共享规则与外围布局，箭头留白不响应格子输入。

### 求和条件联立提示

已有技巧找不到下一步时，增加 45 法则、求和区域相减（消去共有格）和受行列宫互异约束的局部组合筛选。覆盖小杀手、杀手笼、四数和及 XV；仅完整九格互异区域允许使用总和 45，缺一门的八格区域不适用。小杀手斜线不额外要求数字互异。

最多枚举七个未知格；全局与单个方程都有确定的节点预算，未完整检查的组合不会用于候选排除。不读取保存的答案，也不进行整盘试填。中英日解释依次展示原始求和条件、已填数字、共有格相消、局部组合和候选排除，再由玩家应用到笔记。保留撤销及后续提示进度。

### 无缘数独
