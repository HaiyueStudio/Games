# 流光数独 / LED Sudoku

一个独立的 Haiyue 游戏，入口 `games/led-sudoku/index.html`，manifest ID `led-sudoku`。原 `sudoku` 游戏保持独立。

## 构建与启动

```sh
cd Games
npm run build:target -- game:led-sudoku
python3 -m http.server 8317 --bind 127.0.0.1
```

打开 http://127.0.0.1:8317/games/led-sudoku/ 。需要支持 WebGPU 的浏览器。本游戏使用 Haiyue `World`、`Camera3D`、`Mesh3D`、`BasicMaterial`、`Render3DSystem` 渲染灯管棋盘，DOM 承载响应式设置和可访问输入。`@haiyue/engine/experimental` 的公开 `RenderIntegration`、`requireEngineDevice` 依赖已在 manifest 标识。仅维护一张 1260² GPU 纹理，输入后重绘，销毁时释放纹理、世界、引擎、Worker、监听器与计时器。

构建产物包括 `bundle.js` 和 `generator.worker.js`；构建 runner 必须等两个文件都生成。主入口仅编译本游戏和引擎源码，Worker 单独用小范围 tsconfig 编译，避免出题 Worker 和小游戏构建重新检查全部游戏。`preview:build` 会复制 Worker、HTML 和 CSS。

## 玩法与规则

- 青色是不可改的完整已知数；琥珀色是可填写的局部灯段线索；绿色是玩家数字；红色表示错误。
- 亮灯段必须包含在答案中；暗灯段是未知，**不代表该段必须熄灭**。七段位序为上、右上、右下、下、左下、左上、中。中间段 `0x40` 排除 1、7。
- 候选数、单候选提示、完整单元的隐性唯一位置提示、推理解释、自动求解、三档难度、新局、自动存档均保留；新增笔记、撤销、擦除、键盘操作、计时、辉光开关。
- 点击“新数独”打开设置面板，选择三档难度和额外规则，点击“开始新数独”后生效；关闭面板不改变当前棋局。
- LED 灯管是默认开启的规则；关闭后使用普通数字和无灯段约束的唯一解题目。可以组合对角线、缺一门、杀手、连续数（Renban）、相邻连续（差 1）。
- 所有可填的 LED 格始终展示七段灯管，零亮段显示全暗灯管；缺一门黑格使用 ×，不显示灯管。
- 候选输入按钮按 1–9 九宫格排列；计时使用 LED 灯管数字。完成时棋盘边框缓慢闪烁四次后保持亮起，撤销完成或开始新局会恢复；减少动态效果设置下仅保持发光。
- 缺一门：每行、列、宫各有一个预设黑格。黑格不填，其余八格使用 1–9 且不重复，**不要求填齐 1–9，也不固定全盘缺同一个数**。隐性唯一位置只用于九个有效格的完整单元。
- 杀手：连通虚线笼内不重复，数字和等于笼左上角标注。笼覆盖全部非黑格，可与 LED 及少量完整已知数混合。
- Renban：紫线上的不同数字构成连续整数，顺序不限。
- 相邻连续：白点两侧差 1；所有差 1 的边都标点，所以无点的相邻非黑格不能差 1。与 Renban 是独立开关。
- 对角线与缺一门组合时仅要求对角线上可填格不重复。
- 数比：24 条相邻格大小关系，符号尖端指向较小的数字；未填的端点也会排除不可能的 1 或 9。与差 1 白点共用边界时，符号沿边界错开。
- 多对角线：三条带编号的金色虚线贯穿斜向格子，连接盘面边缘。每条线上的有效格不重复，短线不要求出现全部 1–9。斜线在终盘求解前生成，属于真实求解约束；缺一门黑格不参与。
- 排除点：交点圆圈影响周围四格。普通数字圆圈排除该数字；琥珀 LED 圆圈排除所有包含已亮灯段的数字，暗段未知。例如单独左上竖管排除 **4、5、6、8、9**，左上竖管加底横管排除 **5、6、8、9**。候选面板列出所选格涉及的实际排除集合。关闭 LED 后只生成普通数字排除点。生成时避开黑格和相邻圆圈。
- 奇偶：24 个带标记的格子，蓝底＋“偶”只允许 2、4、6、8，红底＋“奇”只允许 1、3、5、7、9，无标记不限制。
- 显示答案需游戏内确认，并标记辅助完成；撤销答案后仍保留“使用过辅助”的记录。

规则资料：[2025 全国数独锦标赛题型说明（缺一门）](https://www.sport.gov.cn/stzx/n5434/c28838581/part/28838591.pdf)、[泰安市体育局比赛题型说明（对角线、杀手、连续）](https://tyj.taian.gov.cn/art/2024/11/16/art_45326_10298555.html)、[数独小栈 Renban 规则](https://variantsudoku.top/puzzles/70)。

## 生成与唯一性

`rules.ts` 为无平台依赖的确定性模型。由 seed 产生随机合法终盘，再生成黑格、连通杀手笼、Renban 路径和全标差 1 边。逐格移除完整已知数，替换为严格小于完整数字的灯段子集或空格。每次变更均在**全部有效规则和灯段约束**下用 MRV 回溯搜索至最多两解；仅在搜索完成且恰有一解时接受。

搜索预算耗尽会恢复刚移除的线索，绝不把未完成搜索当成唯一性证明。因此难度是线索密度/灯段数量目标（35 / 25 / 17 个完整已知数），不是人类解题技巧评级，也不承诺每次都达到该数量。完整终盘在 Worker 内搜索，失败或超时显示可重试错误，不回退到主线程计算。

`generator-client.ts` 使用带类型、版本和请求 ID 的专用 Worker 消息，替换新请求时取消旧请求，拒绝旧回包和重复回包。存档通过独立 `led-sudoku` 槽保存题目、解、笔记、进度、计时和辅助标记；恢复前校验结构与解的一致性。撤销历史仅在当前会话保留。

## 确定性复现与验证

- 标准：`?seed=20260920`
- 全组合：`?seed=20260920&diagonal=1&missing=1&killer=1&renban=1&consecutive=1`
- 难度：`&difficulty=easy` / `normal` / `hard`
- 普通数独：`?seed=20260920&led=0`（默认 `led=1`）
- 四种新增规则：`?seed=20260920&inequality=1&multiDiagonal=1&exclusion=1&parity=1`
- 带 seed 的 URL 每次载入重建相同题目；普通 URL 恢复自动存档。

```sh
node --experimental-strip-types --test games/test/led-sudoku.test.mjs
npm run typecheck
npm test
npm run build
```

86 项单元测试覆盖原有 32 种规则组合 × 3 档难度、新规则 15 种非空组合 × LED 开关并混合旧规则、全部十个开关同时开启、唯一解、LED 对唯一性的实质贡献、普通模式、旧存档兼容、按开关生成提示文案、种子复现、所有约束、短斜线及黑格提示安全、存档损坏、不可变输入转换、Worker 取消/旧回包/错误。`browser-smoke.mjs` 接受 Codex 浏览器 `tab`，`run()` 重放原有 16 项交互检查，`runVariants()` 增加四种规则控制、候选过滤、全部规则存档恢复、普通模式、完成撤销等 9 项检查；均只使用公开 DOM 与输入，不依赖调试后门。截图及人工视觉检查记录见 `evidence/`，四种新规则使用 `variants-` 前缀。
