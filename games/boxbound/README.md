# Boxbound · 盒中漫游

使用 Haiyue 引擎公共 3D/ECS/存档接口制作的递归推箱游戏，入口为 `games/boxbound/`。首页支持新游戏、继续、说明、退出和 5 个独立存档。

## 地图与章节

大地图「新手村」包含 10 个原创立体关卡。北侧红盒进入 Parabox 致敬馆，馆内十一个章节盒子分别包含：

| 章节 | 关卡 | JSON 目录 |
| --- | --- | --- |
| Intro · 入门 | 1–9 | `levels/parabox/intro/` |
| Enter · 进入 | 1–18 | `levels/parabox/enter/` |
| Empty · 空盒 | 1–14 | `levels/parabox/empty/` |
| Eat · 吞入 | 1–12 | `levels/parabox/eat/` |
| Reference · 引用 | 1–10 | `levels/parabox/reference/` |
| Swap · 交换 | 1–5 | `levels/parabox/swap/` |
| Center · 中心 | 1–14 | `levels/parabox/center/` |
| Clone · 克隆 | 1–24 | `levels/parabox/clone/` |
| Transfer · 转移 | 1–29 | `levels/parabox/transfer/` |
| Open · 开放 | 1–12 | `levels/parabox/open/` |
| Flip · 镜像 | 1–8（当前社区数据） | `levels/parabox/flip/` |

共 165 个可完成的小世界（155 个致敬谜题），406 个房间节点、699 个初始盒子。关卡选择发生在世界中：新手村 → 致敬馆 → 章节 → 关卡，没有单独的关卡列表页。红色方块 NPC「红方」向原作致敬。

布局使用 [Asymetry1021/Parabox 的公开社区转录](https://github.com/Asymetry1021/Parabox/blob/main/levels.json)，保留其前十一章编号（9/18/14/12/10/5/14/24/29/12/8）。`parabox-source.json` 保存采用的原始 RLE；这是社区数据，非官方关卡导出。原作由 [Patrick Traynor](https://www.patricksparabox.com/) 创作；模型、材质、NPC 和 MIDI 音效由本项目实现，没有使用原作图像或音频。

每个关卡单独一个 JSON，允许在文件内放置它的多个内部房间。`levels/index.json` 引用完整世界，各世界通过 `$ref` 引用章节或关卡：

```text
levels/index.json
├── islands/world.json → level-01.json … level-10.json
└── parabox/world.json
    ├── intro/world.json → intro-01.json … intro-09.json
    ├── enter/world.json → enter-01.json … enter-18.json
    ├── empty/world.json → empty-01.json … empty-14.json
    ├── eat/world.json → eat-01.json … eat-12.json
    ├── reference/world.json → reference-01.json … reference-10.json
    ├── swap/world.json → swap-01.json … swap-05.json
    ├── center/world.json → center-01.json … center-14.json
    └── clone/world.json → clone-01.json … clone-24.json
```

共 127 个地图文件。`worlds`、`rooms`、`levels` 可混合内嵌对象和 `{ "$ref": "relative/path.json" }`。路径相对于引用文件解析，限制在 `levels/` 内；文件引用必须无环，房间 `inside` 引用允许自包含和循环。

## 操作与完成

| 操作 | 按键 |
| --- | --- |
| 移动／推箱／从门进入 | WASD 或方向键 |
| 跳跃 | J；单按原地跳，配合方向跨越一格高度 |
| 下钻／进入面前盒子 | K |
| 返回 | E，或从可通行边界走出 |
| 撤销 | Z，反向播放动作和进出缩放 |
| 重玩独立关卡 | R |
| 退出当前独立关卡 | Esc；在章节／馆内返回一层，在大世界返回首页 |

Parabox 致敬馆和十一个章节地图均在南侧中央设有绿色箭头与返回标牌。从出生点向南走两步即可离开：章节回到致敬馆，致敬馆回到新手村。入口宽 0.82 格，角色可通行，箱子不能推出。E 快捷返回仍保留。规则版本 12 会修正循环引用中的旧导航路径，并给旧存档补入五个新章节；保留当前位置、已移动箱子和通关记录，原有出口继续可用。

原创关卡要求箱子与同色目标匹配，最后角色站上笑脸终点。Parabox 关卡使用深灰色、不限颜色的箱子目标；保持平面拓扑，J 只能原地跳，不能攀爬绕过谜题。

完成后先播放开心跳跃、转圈、大笑及通关音效，再连续缩放回到该独立关卡外的一层：原创关卡回群岛，Parabox 关卡回所属章节。终点在内部子盒中时，返回到关卡入口所在的章节。落点被占据时寻找附近安全地面；没有落点就留在当前房间。

再次进入带 `levelEntry` 标记的关卡，会恢复该关内部仍在区域中的初始物件，保留已获得的通关记录，允许再次庆祝和返回。R 使用相同的内部恢复范围，并清除当前关完成标记以重玩。移出整关区域的物件、外层布局和其他关卡不受重置影响；外来物件不删除，内部冲突时寻找安全位置。撤销可恢复进入前的状态。

## 普通盒子与独立关卡

关卡盒子使用同一 `Box` 数据和推动／进入规则。独立标记只定义生命周期边界，优先级另行配置：

```json
{
  "id": "my-puzzle-box",
  "pos": [3, 0, 5],
  "size": 1,
  "inside": "my-puzzle-room",
  "fixed": false,
  "portal": true,
  "levelEntry": true,
  "entryPriority": "enter",
  "required": false,
  "color": "blue"
}
```

- `entryPriority: "enter"`：先进入；进入不可行时再尝试推动。
- `entryPriority: "push"`：先推动；推动受阻时再尝试进入，可用于“推到墙边才能进入”的关卡。
- `levelEntry: true`：进入时只重置内部关卡区域。
- `portal: true`：使用内部作者指定的出生点，支持封闭关卡；不再要求盒子固定。
- 普通解谜容器默认先推后进。内部入口被另一个容器占据时，先尝试推动占用物，受阻后继续向内进入；失败事务整体撤回。

`Room.doorWidths` 依次为东、西、南、北的入口净宽。角色宽 0.72，常规窄门宽 0.82，箱子宽 1；窄门限制箱子离开，宽门允许跨界运输。开放的平面盒内可以从非中央的开放边缘推出物件。自包含关卡根节点通过 `recursiveRoot` 保持循环外出语义，不误跳到章节。

## 3D 渲染与连续进入

带地图的盒子使用半透明立方体外壳，内部在真实高度上绘制地面、墙、目标、箱子、装饰和机关。盒内场景按 `盒子边长 / 内部房间边长` 缩放，不再使用盒顶的平面缩略图。

只展开第一层子场景：该层中的嵌套盒子使用终止 LOD 模型，不继续展开它们的内部。循环引用不会无限创建实体。当前房间和外层邻居共用盒体绘制方法；墙体、模型和材质由既有对象池与缓存复用。

角色与箱子进出时都复用原来的实体：按稳定的角色/箱子标识保留各模型部件，在同一空间坐标内移动和缩放。运输中的箱子从盒内预览及外景静态绘制中排除，动画结束后原模型保持可见，不使用淡出替身。

盒内 LOD 与正式场景共用墙体、墙顶、箱子的材质颜色，并保持相同的地面铺装颜色。

进出时将源场景和目标场景换算到同一空间坐标，保留外层几何，提升目标房间的细节，再用 820ms 连续镜头缩放进入；退出反向缩放。画布始终不透明，没有淡出遮罩或中点切屏。结束后回收过渡期间保留的几何，留下当前房间及一层完整父场景。

`space-view.ts` 通过实际路径的容器尺寸、当前位置和内部尺寸组合坐标变换，支持跨多层返回及同名空间的不同实例。小盒子的内部地板略高于外壳底面，避免外层地板遮住内部模型。

在盒内，完整父场景与当前房间共用 `drawRoom` 绘制流程，保留原有地面、连续圆角墙、目标笑脸、箱子侧面标记、装饰及机关，不再用单独的简化外景重建；只向外展开一层，子场景继续使用有限 LOD。外面一格按真实比例显示。例如一格盒子装着 7×7 的地图，外部一格等于内部 7×7；四角、墙、箱子、树木一起缩放。使用透视投影，并依据关卡 JSON 的 `planar` 区分视角：`planar: true` 的平面关卡使用与网格对齐的顶部视角；其他支持跳跃的空间关卡使用 X 方向 45° 俯视、Y 方向 10° 偏转。两种视角均按窗口比例适配到 85% 边界占比；进出同类盒子连续缩放，跨类型时平滑转动相机，保留首帧位置。3D 关卡中，按相机到当前地图格子及角色的视线段检测外层模型包围盒，遮挡的外层物体使用 15% 不透明度，移开后恢复原材质。当前关卡、子层模型及未遮挡的外物保持原样，平面关卡不做外物淡化。几何尺寸和半径使用弱引用缓存，透明材质复用现有有界缓存；静止时仍停止提交渲染。相邻墙体连续连接；不可站立的墙使用圆弧顶，可站立的平台保留平顶。

自包含地图同时绘制父级、当前层和第一层子级中的玩家。各实例共享玩家模型和材质，逐帧同步位置、跳跃、缩放与表情；只控制一个逻辑玩家。显式容器边变换区分同名房间的不同尺度实例，递归路径增长不会继续展开显示层数。自包含根房间首次进入时也以自身容器作为物理父级，章节入口仍保留为返回路径。

外层箱子与当前箱子使用相同的推动时间和完整模型，撤销按相同路径反向播放；盒内 LOD 中的箱子也同步移动。包含当前地图的盒子被推动时，整层父场景及其玩家、机关、标签平滑跟随坐标变化。动画中复用稳定标识的模型部件和共享几何、材质。

自包含根节点从边界向外走，即使房间 ID 和章节导航路径不变，也会产生临时的 `playerCrossing` 记录。渲染使用实际外出容器进行坐标与镜头变换，保持原角色的实体及动画首帧屏幕位置；撤销反向穿过同一容器。该记录只进入有限撤销历史，不写入存档，也不会把外出误判为普通走格；出入音效同步使用它。

自引用房间的箱子运输按物理层级计算，不能用相同房间 ID 把它退化为普通移动。推出时，当前实体继续向父层移动，原有子层实体从内部出口进入当前层；撤销沿同一边界缩回。父层、当前层、第一层子节点共享箱子模型，按稳定实体键交接；有限渲染范围之外的离场实例在动画结束后释放，世界状态中仍只有一份逻辑箱子。

箱子目标边框使用贴地薄层：顶部高度 0.05，略高于地砖顶部 0.045，低于盒内地面基准 0.055。当前场景、完整父场景与盒内预览共用高度，避免外层目标边框放大后凸入盒内地图。

## 机关、装饰与音效

圆形压力按钮可由角色或箱子压住，按房间内 `channel` 打开铁栅栏；离开就升起。按钮与栅栏至少间隔一格。箱子会压住栅栏；箱子离开而角色仍在栅栏位置时，栅栏升起并击退角色，支持撤销。

装饰物使用 `decorations` 数字枚举：1 石头、2 灌木、3 圆冠树、4 松树、5 红方 NPC。阻挡移动和推箱；不会因跳跃绕过不可站立的顶面。

`generate-sfx.py` 生成 11 段原创 MIDI，并渲染为浏览器可播放的 WAV：走动、跳跃、推箱、栅栏升/降、按钮、落地、击退、通关、进入、退出。音频缓存有界，最多 8 个同时播放的声音。

## 代码与资源生命周期

- `model.ts`：整数坐标、有限空间图、进出优先级、推箱与循环判定。
- `levels.ts` / `world-map.ts`：JSON 引用加载、局部重置、五个旧存档升级。
- `completion.ts`：完成与安全返回。
- `scene.ts` / `space-view.ts` / `visuals.ts`：3D、有限 LOD、统一坐标缩放及动作。
- `history.ts`：最多 300 步历史，共享不可变房间定义。
- `audio.ts` / `sound-events.ts`：缓存音频和确定性音效事件。

静止时不重复更新模型、提取场景或提交绘制；输入、动画与窗口变化会唤醒渲染。重建复用对象，较小房间释放多余实体，几何/材质缓存有上限；销毁移除监听并释放场景、标签和缓存。连续进出章节的缩放保留对象也纳入资源检查。

## 验证与边界

`parabox-chapter-solutions.json` 保存前三章全部 41 关的可复现操作路径，`parabox-advanced-solutions.json` 补充新章节 47 关路径，测试逐步检查状态有效性、通关、返回章节、再次进入及内部重置。额外覆盖跨连续边界退出及窄门的原子回滚。

本轮只修改 Games，不需要引擎或全库测试。使用 Boxbound 的 TypeScript、ESLint、规则与资源验证器测试、单游戏构建，以及共享 Chrome/WebGPU runner 的确定性场景。

这是扩展中的 3D 规则实现，不是原作所有机制的完整复刻。目前覆盖普通吞入、有限引用与克隆共享空间；无限外层特殊空间等后续机制仍未完整实现。关卡导入和基础操作验证不等同于原作所有机制的完整一致性验证。

历史局部验证保留在 `.artifacts/boxbound/validation-v13.json`、`validation-v14.json`、`validation-v15.json`；它们对应历史构建，不能替代当前版本证据。

当前版本证据见 `.artifacts/boxbound/validation-v33.json`（新手村入口与宽栅栏）；章节排布证据见 `validation-v32.json`；新增章节与规则证据见 `validation-v31.json`；v25 记录贴地目标标记，v24 记录正交投影与完整外墙，v23 记录相机角度与 85% 视野调整，v22 记录自引用箱子跨层动画修复，v21 记录父场景完整渲染和同步推动，v20 记录自包含出口动画修复，v19 记录固定视角和递归玩家显示，v18 记录总馆和章节出口修复。

## 第四至第八章与顶部表情（v27）

新增 65 个独立 JSON 谜题。`cloneOf` 指向原盒子的 ID，克隆共享同一个 `inside` 房间和动态物件，向边界走出时从原盒子出现。容器在普通推动和进入都失败时，可从迎面开口吞入受阻的可移动箱子；失败会原子回滚。循环推箱依赖仍使用事务内的访问集合检测。只有角色终点的关卡同样能够完成。`void` 标记原作空域：可推箱子，不能从外部进入其盒子或越界导出，E 返回章节仍有效。封闭外壳内出生（如 Clone 18）通过 `entryRoom` 直接还原真实内部出生点，不移动挡在外层出生占位上的盒子。

角色正面表情同时映射到顶面：复用有厚度的浅色标记模型、缓存材质和角色自身的实体池，不引入每帧贴图上传。微笑、大笑、疲惫、困惑和转圈动画共用现有状态；递归玩家显示也复用相同部件。

新增关卡逐一验证入口、合法移动、R 重置和 E 返回；通关回放范围以 `parabox-advanced-solutions.json` 中记录的路径为准，不将限时求解器未找到路径视为不可解或已验证通关。新增章节的构建与浏览器证据见 `.artifacts/boxbound/validation-v27.json`。

进出递归盒子期间，完整父场景和外层角色始终保留；角色副本同步原角色的位置、表情和缩放。使用引擎 batched 配置的视锥剔除，不用裁成一格外景。独立关卡不再悬浮编号标签，已完成的盒子顶角插红旗；章节名称仍保留。普通移动按箱子的实时包含关系穿越循环，Esc 则通过独立关卡入口返回所属章节，二者不混用。

普通移动和同层推动使用 300ms 小跳动画；上下台阶保持 420ms。深灰目标框在当前层、父场景及盒内 LOD 中保持一致。平面场景跳过外物透明检测；静态墙体拼接按房间弱引用缓存，墙体或门宽变更会失效；实体诊断列表只在模型集合变化时更新。

房间有六种固定主题：`meadow` 绿、`rose` 红、`ocean` 蓝、`violet` 紫、`amber` 金、`teal` 青。加载世界时根据初始嵌套图自动分配，已收录地图的不同父子节点均有色差；同一个自引用／克隆房间维持同色。推动盒子不重新配色，旧存档无需重置。可在房间 JSON 中设置 `"theme": "rose"` 显式指定。主题统一决定深浅棋盘地砖、墙身、墙顶和底座，当前层、父场景与 LOD 共用材质；功能性箱子、目标和角色不染色。环境光强度从 1 提高至 1.45，使用接近中性的天光；方向光照保留，阴影默认关闭。

### 紧凑章节布局

Parabox 章节默认每行 4 关，关卡之间留一格宽通道；16 关以内使用 11×11 章节盒子。Enter 的 18 关使用 13×13。Transfer 改为 6×6 容量、每行 6 关，章节地图由 19×19 缩至 15×15；Clone 改为 5×5 容量、每行 5 关，由 15×15 缩至 13×13，保留全部 29/24 关。存档版本 15 迁移这两个章节的地图边界、关卡位置和返回坐标，避开旧玩家位置与新入口重叠，保留内部谜题及通关进度。存档布局版本 13 只迁移章节外层、入口位置和返回坐标，保留关卡内部状态及通关进度。桌面与手机截图、浏览器验证见 `.artifacts/boxbound/compact-chapters/`。

地砖改为无细缝、无厚度的棋盘平面，每格两个三角形，移除凸起的薄圆角矩形。不可站立墙的九宫格凸点替换为低细分连续圆弧顶，每格屋顶 32 个三角形；相邻单元共享轮廓和法线，不生成内部侧面，L/T 接缝及窄入口保持原边界。普通可站立墙仍为平顶，碰撞规则不变。当前层、父层、盒内预览使用同一模型生成器；相同形状跨房间复用几何体，平面标记随地面降低。

### 新手村入口与可配置宽栅栏（v33）

新手村在 z=12 用不可攀上的围墙横贯地图，只留下 x=7–9 的三格铁栅栏。左墙前的按钮位于 [5,0,14]，右墙前的普通箱子位于 [11,0,14]；附近装饰物留出推箱路线。移除大世界提示中直接解释按钮解法的文案，由行走、踩按钮和推箱反馈自然展示规则。

栅栏 JSON 的 `width` 是沿 `axis` 的格数（正整数，省略为 1），`pos` 是占地第一格。例如 `{"id":"island-gate","pos":[7,0,12],"axis":"x","width":3,"channel":"island"}` 覆盖 [7,0,12]、[8,0,12]、[9,0,12]。模型、LOD、碰撞、上方禁跳、外层阻挡预览与按钮间距验证共用占地范围。任意一格有箱子时整扇栅栏保持降下；最后一个箱子移开后，位于栅栏范围内的角色从实际接触格被弹回。
