# Boxbound 性能与资源生命周期验证

本地 Chrome/WebGPU 诊断，渲染修订 9、规则版本 5。只修改 Games 内的 Boxbound 和专用验证文件，没有修改引擎；按用户要求没有运行全库测试。最终源码、构建、截图和前后性能证据指纹见 `validation-v9.json`。

发现与修复：

- 原先每步销毁/重建整个房间，96 次移动新建 71,520 个渲染实体。现在复用 Entity / Mesh3D / Transform 和标签节点，同一负载新建 0 个实体；小场景立即销毁多余部件，几何和材质采用有界共享缓存。
- 原先静止模型每帧重写变换，摄像机、标签和场景提取也持续工作。现在只写变化的变换，静止画面按需渲染，输入与动画继续正常运行。静止采样期变换写入和场景提取均为 0；原地跳跃和窗口尺寸变化均能唤醒渲染。
- 原先 R 重玩直接追加历史，不遵守 300 步上限。现在移动/重玩统一限制 300 步；快照共享未修改的地图定义，角色、箱子、完成列表、跨界记录仍相互隔离。自动保存每步执行，存档摘要只在进入菜单时读取。
- 场景销毁幂等，移除更新/尺寸/设备恢复监听，清空状态和 CPU 资源引用。四次创建、展示、销毁后，实体、部件、标签、CPU 几何与材质缓存均为 0，GPU 每次回到相同引擎基线。

同机固定负载实测：

| 指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 同房间移动/场景更新中位数 | 18.41 ms | 2.71 ms |
| 切房间更新中位数 | 8.14 ms | 1.26 ms |
| 运箱状态更新中位数 | 10.05 ms | 1.52 ms |
| 96 次移动新建实体 | 71,520 | 0 |
| 静止采样期场景提取 | 60 | 0 |

单步 CPU 更新中位数降低约 85.3%。计时包含规则/场景更新，不是整帧 FPS；真实帧等待另行记录，前后使用独立浏览器和相同负载。重复移动、切房间和运箱的 GPU 资源及 CPU 对象数量均在预热后稳定。销毁后保留的 1 个 buffer、2 个 texture 属于仍存活的引擎/画布基线。改动前 GPU 资源也未表现出持续增长，因此没有把对象分配抖动误称为 GPU 泄漏。JS heap 仅作观察，未强制 GC，不据此断言所有长期内存问题已消除。

验证：

- Boxbound 规则/历史测试 58 项 + 性能验证器测试 10 项，共 68 / 68 通过。
- 性能/资源浏览器断言 12 / 12 通过，覆盖资源稳定、销毁回收、静止无重复工作和唤醒。
- 原玩法浏览器 18 / 18 场景、602 条断言通过，覆盖撤销动画、外墙显示、压力机关、进出箱子、上下台阶、通关、五槽存档和手机布局；没有 GPU 或未分类浏览器错误。
- 独立 TypeScript、ESLint、正式 Boxbound 构建、`git diff --check` 通过。已目视检查性能结束画面、撤销运箱、出口外墙和手机截图。
